# Глава 19. Архитектуры: кодировщик, декодировщик и кодировщик-декодировщик

> **Часть 4 — Трансформер** · Уровень: Средний
>
> **В этой главе вы узнаете:** как исходный трансформер соединяет кодировщик и декодировщик через перекрёстное внимание · как модели только с кодировщиком и только с декодировщиком строятся из тех же блоков · какое семейство подходит для какой задачи и почему сегодня доминируют декодерные модели

## Три задачи — три формы

Рассмотрим три задачи. (1) Определить, положительный или отрицательный отзыв о товаре. (2) Перевести русское предложение *«Кошка спит на диване»* на корейский: *«고양이가 소파에서 자고 있다»*. (3) Продолжить текст, который начинается словами «Once upon a time» («Жили-были»).

В первой задаче весь вход доступен сразу, а выход — одна метка; модель может читать каждое слово в обоих направлениях. Во второй задаче есть входная последовательность и *другая* выходная последовательность, которая создаётся слово за словом. В третьей есть только одна последовательность, и модель продлевает её вправо. Эти три формы соответствуют трём семействам моделей-трансформеров: **модели только с кодировщиком** (encoder-only), **архитектуре «кодировщик-декодировщик»** (encoder–decoder) и **модели только с декодировщиком** (decoder-only).

Все три строятся из блока главы 18. Они различаются только двумя вещами: *какую маску* использует самовнимание и *есть ли перекрёстное внимание* ко второй последовательности. Если это понять, то «зоопарк» названий моделей — BERT, GPT, T5 и другие — становится гораздо проще.

## Исходный трансформер: кодировщик и декодировщик

Трансформер из статьи «Attention Is All You Need» создавался для машинного перевода и продолжал линию моделей «последовательность в последовательность» из главы 13. В нём два стека.

**Кодировщик** (encoder) читает исходное предложение. Это стек из $N$ блоков с *немаскированным* самовниманием: каждый исходный токен может смотреть на любой другой исходный токен, слева и справа. Выход кодировщика — последовательность векторов $H = (h_1, \dots, h_n)$, по одному на исходный токен. Каждый вектор обогащён контекстом всего предложения. Этот выход часто называют **памятью** (memory).

**Декодировщик** (decoder) создаёт целевое предложение по одному токену. В каждом блоке декодировщика не два, а *три* подслоя:

1. **маскированное самовнимание** по уже созданным целевым токенам с каузальной маской из главы 16;
2. **перекрёстное внимание** (cross-attention), в котором запросы приходят из декодировщика, а ключи и значения — из памяти кодировщика;
3. полносвязная сеть.

У каждого подслоя есть своя остаточная связь и нормализация, как в главе 18. Перекрёстное внимание — это версия внимания Бахданау из главы 14 для трансформера. Если $Y$ — матрица векторов декодировщика (одна строка на целевой токен), то оно вычисляет

$$
\text{CrossAttention}(Y, H) = \text{softmax}\!\left(\frac{(Y W^Q)(H W^K)^\top}{\sqrt{d_k}}\right) H W^V .
$$

Единственное отличие от самовнимания состоит в том, что запросы и ключи приходят из *разных* последовательностей. Поэтому матрица оценок имеет размер $m \times n$, где $m$ — длина целевой последовательности, а $n$ — длина исходной. Когда декодировщик собирается выдать *소파에서* («на диване»), его запрос может найти векторы кодировщика для *на диване*, хотя порядок слов в русском и корейском различается. Маска в перекрёстном внимании не нужна, потому что весь исходный текст известен заранее.

Обучение использует **метод teacher forcing** («принуждение учителем»), как в главе 13: декодировщик получает правильный целевой префикс (сдвинутый на одну позицию) и учится предсказывать каждый следующий токен. Благодаря каузальной маске все позиции обрабатываются параллельно. При выводе кодировщик запускается один раз, а декодировщик — многократно, добавляя по одному созданному токену.

## Модели только с кодировщиком

Если оставить только стек кодировщика, получится модель только с кодировщиком. Её самовнимание двунаправленное, поэтому каждый выходной вектор зависит от **двунаправленного контекста** (bidirectional context) — и от слов до, и от слов после. Это идеально для задач *понимания*: классификации, распознавания именованных сущностей, ответов на вопросы путём выделения фрагмента текста и получения векторных представлений предложений для поиска (глава 37).

Самый известный пример — BERT (глава 22). Кодировщик видит весь вход, поэтому его нельзя обучать простым предсказанием следующего токена: ответ был бы виден. Вместо этого BERT использует **маскированное языковое моделирование** (masked language modeling): часть входных токенов заменяется специальным токеном `[MASK]`, и модель учится восстанавливать их по контексту с обеих сторон (глава 21). Цена такого подхода в том, что модель только с кодировщиком не является естественным генератором текста: у неё нет встроенного способа создавать длинную последовательность слева направо.

## Модели только с декодировщиком

Если оставить только стек декодировщика и убрать подслой перекрёстного внимания, получится модель только с декодировщиком: блоки с каузальным самовниманием и FFN, больше ничего. Её обучают с самой простой целью — **предсказанием следующего токена** (next-token prediction), то есть каузальным языковым моделированием: на каждой позиции $t$ нужно предсказать токен $t+1$ по токенам $1, \dots, t$. Такая архитектура у семейства GPT (глава 23) и у большинства современных LLM, включая LLaMA и родственные модели (глава 25).

Как модель только с декодировщиком может переводить, если у неё нет кодировщика? Она рассматривает исходный текст как начало текста. Вход «Russian: Кошка спит на диване. Korean:» — это префикс, а перевод — его естественное продолжение. Каузальное самовнимание по префиксу играет ту роль, которую в архитектуре «кодировщик-декодировщик» играло перекрёстное внимание: корейские токены смотрят назад на русские.

Почему победила эта простая конструкция? Здесь действуют сразу несколько причин:

- **Одна единая цель обучения.** Каждый токен каждого текста — обучающий пример, поэтому не нужны размеченные данные или особая схема маскирования.
- **Любая задача — это текст.** Классификацию, перевод, суммаризацию и диалог можно записать как «продолжи этот текст», что ведёт к обучению в контексте (глава 23).
- **Простота при масштабировании.** Один стек одинаковых блоков легко масштабировать, распараллеливать и оптимизировать; законы масштабирования (глава 27) изучались в основном на таких моделях.
- **Эффективная генерация.** При каузальной маске ключи и значения предыдущих токенов не меняются, поэтому их можно кэшировать (KV-кэш, глава 36).

## Модели «кодировщик-декодировщик» сегодня и префиксная модель

Архитектура «кодировщик-декодировщик» не исчезла. T5 переформулировала все задачи NLP в виде «текст на входе — текст на выходе» с кодировщиком и декодировщиком, а BART соединила двунаправленный кодировщик с авторегрессионным декодировщиком. Такие модели остаются сильными в задачах с чётким входом и выходом, например в переводе и **суммаризации** (summarization). Кодировщик читает вход в обоих направлениях, а декодировщик может сосредоточиться на генерации.

Между двумя крайностями есть компромисс — **префиксная языковая модель** (prefix language model, prefix LM). Она использует один стек, как декодировщик, но со смешанной маской: токены префикса (входа) смотрят друг на друга в обоих направлениях, а токены продолжения — каузально. Код ниже строит небольшую модель «кодировщик-декодировщик» из встроенных модулей PyTorch и печатает три маски рядом.

```python
import torch
import torch.nn as nn

T_src, T_tgt, d = 6, 4, 32
src = torch.randn(1, T_src, d)   # векторы исходного предложения (например, русского)
tgt = torch.randn(1, T_tgt, d)   # векторы уже созданного целевого префикса (например, корейского)

# Кодировщик: каждый токен видит каждый токен, поэтому маска не нужна
enc_layer = nn.TransformerEncoderLayer(d, nhead=4, batch_first=True)
memory = nn.TransformerEncoder(enc_layer, num_layers=2)(src)

# Декодировщик: каузальное самовнимание + перекрёстное внимание к выходу кодировщика
dec_layer = nn.TransformerDecoderLayer(d, nhead=4, batch_first=True)
decoder = nn.TransformerDecoder(dec_layer, num_layers=2)
causal = nn.Transformer.generate_square_subsequent_mask(T_tgt)  # -inf выше диагонали
out = decoder(tgt, memory, tgt_mask=causal)
print(memory.shape, out.shape)

# Маски трёх семейств для 4 токенов (1 = можно смотреть)
full = torch.ones(4, 4, dtype=torch.int)     # только кодировщик (BERT)
causal01 = torch.tril(full)                  # только декодировщик (GPT)
prefix = causal01.clone()
prefix[:, :2] = 1                            # prefix LM: первые 2 токена видны всем
print(full, causal01, prefix, sep="\n")
```

Первая строка вывода — `torch.Size([1, 6, 32]) torch.Size([1, 4, 32])`: в памяти по одному вектору на исходный токен, на выходе декодировщика — по одному вектору на целевой токен. Затем идут три маски. Маска кодировщика состоит из одних единиц. Маска декодировщика нижнетреугольная. Маска префиксной модели совпадает с каузальной, кроме первых двух столбцов: первые два токена образуют префикс и видят друг друга, а каждый следующий токен видит весь префикс.

Сравним семейства с первого взгляда:

| | Только кодировщик | Кодировщик-декодировщик | Только декодировщик |
|---|---|---|---|
| Маска самовнимания | полная (двунаправленная) | полная в кодировщике, каузальная в декодировщике | каузальная |
| Перекрёстное внимание | нет | да | нет |
| Типичная цель обучения | маскированное LM | seq2seq, маскирование фрагментов | предсказание следующего токена |
| Типичные задачи | классификация, разметка, векторные представления | перевод, суммаризация | генерация, чат, почти всё |
| Примеры | BERT | исходный трансформер, T5, BART | GPT, LLaMA |

## Итоги

- Все семейства трансформеров используют один и тот же блок; они различаются маской самовнимания и наличием перекрёстного внимания.
- Исходный трансформер — это архитектура «кодировщик-декодировщик»: двунаправленный кодировщик создаёт память, а каузальный декодировщик читает её через перекрёстное внимание.
- В перекрёстном внимании запросы приходят из декодировщика, а ключи и значения — из выхода кодировщика.
- Модели только с кодировщиком (BERT) видят двунаправленный контекст и подходят для задач понимания; их обучают маскированным языковым моделированием.
- Модели только с декодировщиком (GPT, LLaMA) используют каузальное внимание и предсказание следующего токена; простота и универсальность сделали их основной архитектурой LLM.
