> **이 장에서 배울 내용:** 원래의 트랜스포머가 교차 어텐션으로 인코더와 디코더를 어떻게 결합하는가 · 인코더 전용 모델과 디코더 전용 모델이 같은 블록으로 어떻게 만들어지는가 · 어떤 계열이 어떤 과제에 맞으며, 오늘날 왜 디코더 전용 모델이 주류인가

## 세 가지 과제, 세 가지 형태

세 가지 과제를 생각해 봅시다. (1) 상품 리뷰가 긍정적인지 부정적인지 판단하기. (2) 러시아어 문장 *«Кошка спит на диване»*를 한국어 *"고양이가 소파에서 자고 있다"*로 번역하기. (3) "Once upon a time"(옛날 옛적에)으로 시작하는 텍스트 이어 쓰기.

첫 번째 과제에서는 입력 전체가 한 번에 주어지고 출력은 레이블 하나입니다. 모델은 모든 단어를 양방향으로 읽어도 됩니다. 두 번째 과제에는 입력 시퀀스와 그와 *다른* 출력 시퀀스가 있으며, 출력은 단어 하나씩 만들어집니다. 세 번째 과제에는 시퀀스가 하나뿐이고 모델은 이를 오른쪽으로 늘려 갑니다. 이 세 가지 형태가 트랜스포머 모델의 세 계열, 즉 **인코더 전용(encoder-only)**, **인코더–디코더(encoder–decoder)**, **디코더 전용(decoder-only)**에 대응합니다.

세 계열 모두 제18장의 블록으로 만들어집니다. 차이는 두 가지뿐입니다. 셀프 어텐션이 *어떤 마스크*를 쓰는가, 그리고 두 번째 시퀀스에 대한 *교차 어텐션이 있는가*입니다. 이것을 이해하면 BERT, GPT, T5 같은 수많은 모델 이름이 훨씬 단순해집니다.

## 원래의 트랜스포머: 인코더와 디코더

"Attention Is All You Need"의 트랜스포머는 제13장의 시퀀스-투-시퀀스 계보를 이어 기계 번역을 위해 설계되었습니다. 스택이 두 개 있습니다.

**인코더(encoder)**는 원문 문장을 읽습니다. *마스크가 없는* 셀프 어텐션을 쓰는 블록 $N$개의 스택이며, 모든 원문 토큰이 왼쪽과 오른쪽의 다른 모든 원문 토큰에 어텐션할 수 있습니다. 출력은 원문 토큰마다 하나씩인 벡터 시퀀스 $H = (h_1, \dots, h_n)$이며, 각 벡터에는 문장 전체의 문맥이 담깁니다. 이 출력을 흔히 **메모리(memory)**라고 부릅니다.

**디코더(decoder)**는 목표 문장을 토큰 하나씩 생성합니다. 각 디코더 블록에는 하위 층이 두 개가 아니라 *세 개* 있습니다.

1. 지금까지 생성된 목표 토큰에 대한 **마스크드 셀프 어텐션**(제16장의 인과 마스크 사용)
2. 쿼리는 디코더에서, 키와 값은 인코더 메모리에서 오는 **교차 어텐션(cross-attention)**
3. 피드포워드 네트워크

제18장에서처럼 각 하위 층에는 잔차 연결과 정규화가 있습니다. 교차 어텐션은 제14장의 Bahdanau 어텐션의 트랜스포머 버전입니다. $Y$가 디코더 벡터의 행렬(목표 토큰당 한 행)이라면 교차 어텐션은 다음을 계산합니다.

$$
\text{CrossAttention}(Y, H) = \text{softmax}\!\left(\frac{(Y W^Q)(H W^K)^\top}{\sqrt{d_k}}\right) H W^V .
$$

셀프 어텐션과의 유일한 차이는 쿼리와 키가 *서로 다른* 시퀀스에서 온다는 점입니다. 따라서 점수 행렬의 크기는 $m \times n$이며, $m$은 목표 시퀀스의 길이, $n$은 원문 시퀀스의 길이입니다. 디코더가 *소파에서*를 내보내려 할 때, 러시아어와 한국어의 어순이 달라도 그 쿼리는 *на диване*에 해당하는 인코더 벡터를 찾을 수 있습니다. 원문 전체를 미리 알고 있으므로 교차 어텐션에는 마스크가 필요 없습니다.

학습에는 제13장에서처럼 **교사 강요(teacher forcing)**를 사용합니다. 디코더는 올바른 목표 접두사(한 위치 밀린 것)를 받아 각 다음 토큰을 예측하도록 학습하며, 인과 마스크 덕분에 모든 위치를 병렬로 처리합니다. 추론할 때는 인코더를 한 번 실행하고, 디코더를 반복 실행하면서 생성된 토큰을 하나씩 덧붙입니다.

## 인코더 전용 모델

인코더 스택만 남기면 **인코더 전용 모델(encoder-only model)**이 됩니다. 셀프 어텐션이 양방향이므로 각 출력 벡터는 앞뒤 단어를 모두 포함한 **양방향 문맥(bidirectional context)**에 의존합니다. 이는 *이해* 과제에 이상적입니다. 분류, 개체명 인식, 텍스트 구간을 골라 답하는 질의응답, 검색용 문장 임베딩 생성(제37장) 등이 그렇습니다.

가장 잘 알려진 예는 BERT(제22장)입니다. 인코더는 입력 전체를 보므로 단순한 다음 토큰 예측으로 학습할 수 없습니다. 답이 보이기 때문입니다. 대신 BERT는 **마스크 언어 모델링(masked language modeling)**을 사용합니다. 입력 토큰 일부를 특수 토큰 `[MASK]`로 바꾸고, 모델은 양쪽 문맥으로 이를 복원하도록 학습합니다(제21장). 그 대가로 인코더 전용 모델은 자연스러운 텍스트 생성기가 아닙니다. 왼쪽에서 오른쪽으로 긴 시퀀스를 만들어 내는 내장된 방법이 없습니다.

## 디코더 전용 모델

디코더 스택만 남기고 교차 어텐션 하위 층을 없애면 **디코더 전용 모델(decoder-only model)**이 됩니다. 인과적 셀프 어텐션과 FFN을 가진 블록뿐, 그 밖에는 아무것도 없습니다. 이 모델은 가능한 가장 단순한 목표인 **다음 토큰 예측(next-token prediction)**, 즉 인과적 언어 모델링으로 학습합니다. 모든 위치 $t$에서 토큰 $1, \dots, t$로부터 토큰 $t+1$을 예측합니다. GPT 계열(제23장)과 LLaMA 및 그 계열 모델(제25장)을 비롯한 대부분의 현대 LLM이 이 아키텍처를 가집니다.

인코더가 없는 디코더 전용 모델은 어떻게 번역을 할까요? 원문을 텍스트의 시작 부분으로 취급합니다. 입력 "Russian: Кошка спит на диване. Korean:"은 접두사이고, 번역은 그 자연스러운 이어짐입니다. 접두사에 대한 인과적 셀프 어텐션이 인코더–디코더에서 교차 어텐션이 하던 역할을 합니다. 한국어 토큰들이 앞의 러시아어 토큰들에 어텐션합니다.

이 단순한 설계가 왜 승리했을까요? 여러 이유가 함께 작용합니다.

- **하나의 통일된 목표.** 모든 텍스트의 모든 토큰이 학습 예제이므로 레이블이 달린 데이터나 특별한 마스킹 방식이 필요 없습니다.
- **모든 과제가 텍스트.** 분류, 번역, 요약, 대화를 모두 "이 텍스트를 이어 쓰라"로 표현할 수 있으며, 이것이 문맥 내 학습(제23장)으로 이어집니다.
- **규모 확장의 단순성.** 동일한 블록 하나의 스택은 확장, 병렬화, 최적화가 쉽습니다. 스케일링 법칙(제27장)도 주로 이런 모델에서 연구되었습니다.
- **효율적인 생성.** 인과 마스크에서는 이전 토큰의 키와 값이 변하지 않으므로 캐시할 수 있습니다(KV 캐시, 제36장).

## 오늘날의 인코더–디코더 모델과 접두사 언어 모델

인코더–디코더 설계가 사라진 것은 아닙니다. T5는 모든 NLP 과제를 인코더–디코더로 "텍스트 입력, 텍스트 출력" 형태로 재구성했고, BART는 양방향 인코더와 자기회귀 디코더를 결합했습니다. 이런 모델은 번역이나 **요약(summarization)**처럼 입력과 출력이 분명한 과제에서 여전히 강합니다. 인코더는 입력을 양방향으로 읽고, 디코더는 생성에 집중할 수 있기 때문입니다.

두 극단 사이에는 절충안인 **접두사 언어 모델(prefix language model, prefix LM)**이 있습니다. 디코더처럼 스택 하나를 쓰지만 마스크가 혼합되어 있습니다. 접두사(입력)의 토큰들은 서로 양방향으로 어텐션하고, 이어지는 부분의 토큰들은 인과적으로 어텐션합니다. 아래 코드는 PyTorch 내장 모듈로 작은 인코더–디코더를 만들고 세 가지 마스크를 나란히 출력합니다.

```python
import torch
import torch.nn as nn

T_src, T_tgt, d = 6, 4, 32
src = torch.randn(1, T_src, d)   # 원문 문장의 벡터(예: 러시아어)
tgt = torch.randn(1, T_tgt, d)   # 지금까지 생성된 목표 접두사의 벡터(예: 한국어)

# 인코더: 모든 토큰이 모든 토큰을 보므로 마스크가 필요 없음
enc_layer = nn.TransformerEncoderLayer(d, nhead=4, batch_first=True)
memory = nn.TransformerEncoder(enc_layer, num_layers=2)(src)

# 디코더: 인과적 셀프 어텐션 + 인코더 출력에 대한 교차 어텐션
dec_layer = nn.TransformerDecoderLayer(d, nhead=4, batch_first=True)
decoder = nn.TransformerDecoder(dec_layer, num_layers=2)
causal = nn.Transformer.generate_square_subsequent_mask(T_tgt)  # 대각선 위는 -inf
out = decoder(tgt, memory, tgt_mask=causal)
print(memory.shape, out.shape)

# 토큰 4개에 대한 세 계열의 마스크 (1 = 어텐션 가능)
full = torch.ones(4, 4, dtype=torch.int)     # 인코더 전용 (BERT)
causal01 = torch.tril(full)                  # 디코더 전용 (GPT)
prefix = causal01.clone()
prefix[:, :2] = 1                            # prefix LM: 처음 2개 토큰은 모두에게 보임
print(full, causal01, prefix, sep="\n")
```

출력 첫 줄은 `torch.Size([1, 6, 32]) torch.Size([1, 4, 32])`입니다. 메모리에는 원문 토큰마다 벡터가 하나씩, 디코더 출력에는 목표 토큰마다 벡터가 하나씩 있습니다. 이어서 세 마스크가 나옵니다. 인코더 마스크는 모두 1입니다. 디코더 마스크는 하삼각입니다. 접두사 언어 모델의 마스크는 처음 두 열을 제외하면 인과 마스크와 같습니다. 처음 두 토큰이 접두사를 이루어 서로를 볼 수 있고, 그 뒤의 모든 토큰은 접두사 전체를 볼 수 있습니다.

계열들을 한눈에 비교하면 다음과 같습니다.

| | 인코더 전용 | 인코더–디코더 | 디코더 전용 |
|---|---|---|---|
| 셀프 어텐션 마스크 | 전체(양방향) | 인코더는 전체, 디코더는 인과 | 인과 |
| 교차 어텐션 | 없음 | 있음 | 없음 |
| 대표적 학습 목표 | 마스크 LM | 시퀀스-투-시퀀스, 스팬 손상 | 다음 토큰 예측 |
| 대표적 과제 | 분류, 태깅, 임베딩 | 번역, 요약 | 생성, 채팅, 거의 모든 것 |
| 예 | BERT | 원래의 트랜스포머, T5, BART | GPT, LLaMA |

## 요약

- 모든 트랜스포머 계열은 같은 블록을 사용하며, 셀프 어텐션 마스크와 교차 어텐션의 유무로 구별됩니다.
- 원래의 트랜스포머는 인코더–디코더입니다. 양방향 인코더가 메모리를 만들고, 인과적 디코더가 교차 어텐션으로 이를 읽습니다.
- 교차 어텐션에서 쿼리는 디코더에서, 키와 값은 인코더 출력에서 옵니다.
- 인코더 전용 모델(BERT)은 양방향 문맥을 보며 이해 과제에 적합하고, 마스크 언어 모델링으로 학습합니다.
- 디코더 전용 모델(GPT, LLaMA)은 인과적 어텐션과 다음 토큰 예측을 사용하며, 단순성과 범용성 덕분에 주류 LLM 아키텍처가 되었습니다.
