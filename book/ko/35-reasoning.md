# 제35장. 추론과 사고의 사슬

> **제7부 — 모델의 적응과 정렬** · 수준: 고급
>
> **이 장에서 배울 내용:** 모델이 "소리 내어 생각"하게 하면 여러 단계의 문제 풀이가 좋아지는 이유 · 자기 일관성, 검증기, 탐색이 추론 시점에 더 많은 연산을 쓰는 방식 · 검증 가능한 보상에 대한 강화 학습으로 추론 모델을 학습시키는 방법

## 바로 답하기와 단계별로 답하기

간단한 문장제를 살펴봅시다.

> 마샤에게는 연필이 12자루씩 든 상자가 3개 있었습니다. 마샤는 동생에게 연필 7자루를 주었습니다. 남은 연필은 몇 자루입니까?

언어 모델에게 숫자만 말하라고 하면, 모델은 맨 첫 번째 출력 토큰에서 답을 내야 합니다. "36"이라고 답하는 모델은 일의 절반만 하고 뺄셈을 잊은 것입니다. 이제 단계를 적어 보라고 해 봅시다.

> 상자 3개 × 연필 12자루 = 연필 36자루. 36 − 7 = 29. 답: 29.

모델이 맞힐 가능성이 훨씬 높아집니다. 최종 답 전에 중간 단계를 적는 것을 **사고의 사슬**(chain-of-thought, CoT) 추론이라고 합니다. Wei 외(2022)는 추론 과정을 적은 풀이 예제 몇 개를 프롬프트에 넣으면(퓨샷 CoT 프롬프팅, 23장 참고) GSM8K(초등 수준 수학 문장제 데이터셋) 같은 산술, 상식, 기호 추론 벤치마크에서 큰 모델의 성능이 크게 향상됨을 보였습니다. Kojima 외(2022)는 예제 없이도 프롬프트에 "Let's think step by step"("단계별로 생각해 봅시다")이라는 문구만 더하면(제로샷 CoT) 큰 향상을 얻을 수 있음을 발견했습니다. 지시 튜닝(33장)과 마찬가지로, 이 효과는 큰 모델에서 강했고 작은 모델에서는 약하거나 없었습니다.

## 소리 내어 생각하는 것이 도움이 되는 이유

간단한 계산적 논거가 있습니다. 트랜스포머(18장)는 생성하는 토큰마다 고정된 양의 연산, 즉 $L$개 층을 한 번 통과하는 연산을 수행합니다. 어떤 문제가 네트워크가 한 번의 통과로 수행할 수 있는 것보다 더 많은 순차적 단계를 요구한다면, 모델은 토큰 하나로 그 문제를 안정적으로 풀 수 없습니다. 그러나 생성된 각 토큰은 맥락에 덧붙여지고, 다음 토큰은 그것에 어텐션을 줄 수 있습니다(16장). 따라서 생성된 텍스트는 **스크래치패드**(scratchpad), 즉 모델이 중간 결과를 적어 두고 다시 읽는 외부 작업 메모리 역할을 합니다. 추론 토큰 $k$개를 생성하면 모델은 답하기 전에 대략 $k$번의 추가 연산 통과를 얻습니다. 트랜스포머에 관한 이론 연구도 이 직관을 뒷받침합니다. 중간 단계를 허용하면 고정 크기 트랜스포머가 풀 수 있는 문제의 부류가 넓어집니다.

두 번째 관점은 확률적입니다. $x$를 질문, $z$를 추론 사슬, $a$를 최종 답이라고 합시다. 모델은 $z$를 생성한 다음 $a$를 생성하므로, 답의 확률은 가능한 모든 사슬에 대한 합입니다.

$$p(a \mid x) = \sum_{z} p(z \mid x)\, p(a \mid x, z).$$

사슬의 각 단계는 쉽고 맞을 확률이 높지만, $x$에서 $a$로 바로 건너뛰는 것은 어렵습니다. CoT는 하나의 어려운 예측을 여러 개의 쉬운 예측으로 나눕니다. 같은 식이 다음 아이디어를 암시합니다. 가능한 사슬이 많으니 여러 개를 샘플링할 수 있다는 것입니다.

## 추론 시점에 더 많은 연산 쓰기

**자기 일관성**(self-consistency, Wang 외, 2022)은 0보다 높은 온도(24장)로 서로 다른 추론 사슬 $N$개를 샘플링하고, 각각에서 최종 답을 뽑아 **다수결 투표**(majority voting)로 가장 많이 나온 답을 반환합니다. 이것은 위의 $z$에 대한 합을 근사합니다. 서로 다른 많은 사슬이 도달하는 답일수록 맞을 가능성이 높습니다. 아래 시뮬레이션은 이 효과를 구체적으로 보여 줍니다. 각 사슬이 맞을 확률은 0.4에 불과하지만, 틀린 사슬들은 서로 다른 답을 내므로 보통 정답이 투표에서 이깁니다.

```python
import random
from collections import Counter

random.seed(0)
CORRECT = 29
WRONG = [27, 31, 33, 36, 41]          # 여러 값에 흩어진 전형적인 실수

def sample_chain():
    # 추론 사슬 하나: 확률 0.4로 정답, 아니면 무작위 실수
    return CORRECT if random.random() < 0.4 else random.choice(WRONG)

def self_consistency(n):
    answers = [sample_chain() for _ in range(n)]
    return Counter(answers).most_common(1)[0][0]   # 다수결 투표

for n in [1, 5, 11, 21]:
    trials = 5000
    acc = sum(self_consistency(n) == CORRECT for _ in range(trials)) / trials
    print(f"N = {n:2d} chains: accuracy {acc:.2f}")
# N =  1 chains: accuracy 0.39
# N =  5 chains: accuracy 0.58
# N = 11 chains: accuracy 0.76
# N = 21 chains: accuracy 0.90
```

여기서 각 오답의 확률은 $0.6 / 5 = 0.12$로 $0.4$보다 훨씬 작으므로, 사슬이 많아질수록 투표가 믿을 만해집니다. 모델이 대부분 *같은* 실수를 한다면 투표는 도움이 되지 않을 것입니다. 자기 일관성은 오류가 흩어져 있을 때만 정확도를 높입니다.

투표는 **테스트 시점 연산**(test-time compute), 즉 학습이 아니라 추론 시점의 추가 연산을 활용하는 방법 중 하나입니다. 다른 방법은 다음과 같습니다.

- **검증기를 이용한 Best-of-N.** 풀이 $N$개를 샘플링하고 별도의 **검증기**(verifier) 모델에서 가장 높은 점수를 받은 것을 고릅니다. **결과 보상 모델**(outcome reward model, ORM)은 최종 답만 채점하고, **과정 보상 모델**(process reward model, PRM)은 각 단계를 채점합니다. Lightman 외("Let's Verify Step by Step", 2023)는 수학에서 과정 감독이 결과 감독보다 더 믿을 만한 검증기를 만든다는 것을 발견했습니다.
- **탐색.** **생각의 나무**(Tree of Thoughts, Yao 외, 2023)는 부분적인 추론 사슬을 나무의 노드로 보고, 각 노드의 여러 후속을 생성하고 평가하여 유망한 가지를 탐색하며, 가지가 틀려 보이면 되돌아갑니다.

이 모든 방법은 추론 비용을 정확도와 맞바꿉니다. 유용한 사고 모형은 이렇습니다. "더 오래 생각하는" 작은 모델이 바로 답하는 큰 모델과 맞먹을 때도 있지만, 질문당 비용은 $N$과 사슬의 길이에 따라 커집니다.

## 모델에게 추론을 가르치기

프롬프팅은 모델이 이미 할 수 있는 추론을 *끌어낼* 뿐입니다. 현대의 **추론 모델**(reasoning model)은 길고 유용한 사고의 사슬을 생성하도록 학습됩니다. 두 가지 아이디어가 핵심입니다.

**자신의 정답 풀이로부터 배우기.** STaR(Zelikman 외, 2022)에서는 모델이 많은 문제에 대해 근거를 생성하고, 정답에 도달한 것들을 남겨 지도 미세 조정에 사용하며, 이 과정을 반복합니다. 모델은 스스로 추론 데이터를 부트스트랩합니다. 이는 **거부 샘플링**(rejection sampling)과 밀접하게 관련되어 있습니다. 많은 풀이를 생성하고 좋은 것만 남기는 것입니다.

**검증 가능한 보상에 대한 강화 학습.** 34장에서 보상은 학습된 보상 모델에서 나왔고, 이는 해킹될 수 있었습니다. 수학과 프로그래밍에서는 더 잘할 수 있는 경우가 많습니다. 프로그램이 최종 답이 참조 답과 같은지, 또는 생성된 코드가 단위 테스트를 통과하는지 확인할 수 있습니다. 이러한 **검증 가능한 보상**(verifiable reward, 예: 정답이면 1, 오답이면 0)은 저렴하고 속이기 어렵습니다. 그다음 모델을 강화 학습으로 학습시켜 이 보상을 최대화합니다. 널리 쓰이는 알고리즘은 **GRPO**(group relative policy optimisation, 그룹 상대 정책 최적화, DeepSeekMath 연구에서 도입됨, Shao 외, 2024)로, 가치 네트워크가 없는 PPO의 단순화 버전입니다. GRPO는 각 문제에 대해 $G$개의 답으로 된 그룹을 샘플링하고, 보상 $r_1, \dots, r_G$를 계산한 뒤, 정규화된 보상을 각 답의 **이점**(advantage)으로 사용합니다.

$$A_i = \frac{r_i - \mathrm{mean}(r_1, \dots, r_G)}{\mathrm{std}(r_1, \dots, r_G)}.$$

그룹 평균보다 나은 답은 양의 이점을 받아 더 확률이 높아지고, 나쁜 답은 확률이 낮아집니다. 보상이 $(1, 0, 0, 1)$인 네 개의 답으로 된 그룹에서는 평균이 $0.5$, 표준 편차가 $0.5$입니다.

```python
import torch
rewards = torch.tensor([1.0, 0.0, 0.0, 1.0])   # 한 문제에 대한 답 4개: 1 = 정답
adv = (rewards - rewards.mean()) / rewards.std(unbiased=False)
print(adv)                                      # tensor([ 1., -1., -1.,  1.])
```

(어떤 표준 편차를 쓰는지, 참조 모델에 대한 KL 벌점을 어떻게 더하는지 등 세부 사항은 구현마다 다릅니다.) DeepSeek-R1(2025) 같은 보고서는 규칙 기반 보상을 이용한 강화 학습으로 모델이 스스로 더 긴 사고의 사슬을 생성하게 되었으며, 여기에는 이전 단계를 점검하고 수정하는 것도 포함되었다고 설명했습니다. 강력한 추론 모델은 교사로도 쓸 수 있습니다. 그 추론 흔적으로 더 작은 모델을 SFT로 학습시키는 것을 **추론 증류**(reasoning distillation)라고 합니다.

## 한계와 열린 질문

- **충실성.** 사고의 사슬은 모델이 생성하는 텍스트이며, 실제로 답을 낸 계산을 기술한다는 보장은 없습니다. Turpin 외(2023)는 모델이 프롬프트의 숨겨진 편향에 영향을 받으면서도 그 편향을 전혀 언급하지 않는 설명을 내놓을 수 있음을 보였습니다. CoT는 성능에 유용하고 투명성에도 부분적으로 도움이 되지만, 믿을 만한 설명으로 취급해서는 안 됩니다.
- **오류가 전파됩니다.** 사슬 초반의 잘못된 한 단계가 이후 추론 전체를 엇나가게 할 수 있으며, 유창한 사슬은 틀린 답을 그럴듯하게 보이게 만들 수 있습니다.
- **비용.** 긴 사슬은 생성 토큰 수를 늘려 추론 비용과 지연(36장)을 키웁니다. 모델이 쉬운 질문에 대해 "과도하게 생각"할 수도 있습니다.
- **검증 가능한 영역이 더 쉽습니다.** 검증 가능한 보상에 대한 RL은 수학과 코드처럼 답을 자동으로 확인할 수 있는 곳에서 가장 잘 작동합니다. 정답 여부를 확인하기 어려운 열린 질문에 대해 비슷한 추론을 어떻게 학습시킬지는 활발한 연구 주제입니다.

## 요약

- 사고의 사슬은 답 전에 중간 추론 단계를 생성하는 것이며, 퓨샷 예제나 "단계별로 생각해 봅시다" 같은 문구로 끌어낼 수 있습니다.
- 생성된 각 토큰이 연산을 더하고 맥락이 스크래치패드 역할을 하기 때문에 CoT가 도움이 됩니다. 하나의 어려운 예측이 여러 개의 쉬운 예측으로 나뉩니다.
- 자기 일관성은 많은 사슬을 샘플링해 다수결 투표를 하며, 검증기(ORM, PRM)와 트리 탐색은 테스트 시점 연산을 쓰는 다른 방법입니다.
- 추론 모델은 자신의 정답 풀이(STaR, 거부 샘플링)와 검증 가능한 보상에 대한 강화 학습(예: GRPO의 그룹 정규화 이점)으로 학습됩니다.
- 사고의 사슬이 반드시 충실한 설명인 것은 아니며, 오류가 전파될 수 있고, 긴 추론은 비쌉니다.

## 연습 문제

1. 트랜스포머가 첫 토큰에서 답을 내야 할 때는 여러 단계의 문제를 풀지 못하다가, 단계를 적어 나갈 때는 풀 수 있는 이유를 자신의 말로 설명하십시오.
2. 시뮬레이션에서 정답 사슬의 확률을 0.4에서 0.25로 바꾸십시오. 다수결 투표가 여전히 도움이 됩니까? `WRONG`에 값이 하나만 있다면 어떻게 됩니까?
3. 보상 그룹 $(1, 0, 0, 0)$에 대한 GRPO 이점을 계산하십시오. 네 답이 모두 정답이라면 어떻게 됩니까? 그런 그룹을 학습에서 건너뛰는 이유는 무엇일까요?
4. 두 단계 문장제를 위한 퓨샷 사고의 사슬 프롬프트를 러시아어로 작성하십시오. 풀이 예제 두 개와 새로운 질문 하나를 포함하십시오.
