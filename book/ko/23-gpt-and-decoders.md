## 번역을 배운 적 없는 모델

큰 디코더 전용 언어 모델에 다음 텍스트를 주고 이어서 쓰게 해 봅시다.

```text
Translate English to Russian.
sea otter => морская выдра
cheese => сыр
peppermint => мята перечная
book =>
```

좋은 모델은 *"книга"*로 이어 씁니다. 이것은 놀라운 일입니다. 이 모델은 입력–출력 쌍으로 된 번역 데이터셋으로 학습된 적이 없습니다. 오직 평범한 텍스트의 다음 토큰을 예측하도록 학습되었을 뿐입니다(제21장). 그런데도 입력 속 세 개의 예시로부터 과제를 알아채고 수행합니다. 가중치는 전혀 바뀌지 않습니다. 이 능력을 **문맥 내 학습**(in-context learning)이라고 하며, GPT 같은 **디코더 전용 모델**(decoder-only model)이 현대 LLM의 기반이 된 주된 이유입니다.

이 장에서는 먼저 이 계열이 어떻게 발전했는지 보고, 다음으로 아키텍처를, 마지막으로 문맥 내 학습 자체를 살펴봅니다.

## GPT에서 GPT-3까지

이야기는 세 단계로 이루어지며, 모두 OpenAI에서 나왔습니다.

**GPT**(Radford et al., 2018) — "Generative Pre-Training". 트랜스포머 디코더를 책 말뭉치에서 인과적 언어 모델링으로 사전 학습한 뒤, 과제마다 미세 조정했습니다. 몇 달 뒤 BERT가 하게 될 방식과 비슷합니다. 핵심 메시지는 **생성적 사전 학습**(generative pre-training)이 여러 과제로 잘 전이되는 표현을 만든다는 것이었습니다.

**GPT-2**(Radford et al., 2019)는 같은 아이디어를 더 큰 규모로 적용했습니다. 파라미터는 최대 15억 개였고, 대규모 웹 페이지 모음으로 학습했습니다. 논문 제목은 도발적이었습니다. *"Language Models are Unsupervised Multitask Learners"*(언어 모델은 비지도 다중 과제 학습자이다). 저자들은 미세 조정 없이도, 과제를 텍스트로 적어 주기만 하면 모델이 요약, 번역, 질의응답을 조금은 할 수 있음을 보였습니다. 예를 들어 기사 뒤에 *"TL;DR:"*를 붙여 요약을 요청했습니다. 이것이 **제로샷**(zero-shot) 사용입니다. 과제는 설명하지만 예시는 주지 않습니다.

**GPT-3**(Brown et al., 2020)는 규모를 다시 1,750억 개 파라미터로 키웠습니다. 논문 *"Language Models are Few-Shot Learners"*는 프롬프트에 예시 몇 개를 넣으면 어떤 일이 일어나는지 체계적으로 연구했습니다. 모델이 클수록 성능이 꾸준히 좋아졌고, 가장 큰 모델에서는 **퓨샷 프롬프팅**(few-shot prompting)이 때때로 미세 조정된 시스템에 근접했습니다. GPT-3 이후 이 분야는 하나의 큰 사전 학습 모델을 입력 텍스트로 제어하는 범용 도구로 다루기 시작했습니다.

## 디코더 전용 아키텍처

아키텍처 측면에서 GPT 모델은 제19장의 디코더에서 교차 어텐션을 뺀 것입니다. 즉 **인과적 마스크**(causal mask)를 쓰는 트랜스포머 블록의 스택입니다. GPT-2는 이후 대부분의 모델이 유지한 배치를 도입했습니다.

1. 토큰 임베딩과 학습되는 위치 임베딩의 합(제17장).
2. $L$개의 블록. 각 블록은 **사전 정규화**(pre-normalization)를 씁니다: $x \leftarrow x + \text{Attn}(\text{LN}(x))$, 그다음 $x \leftarrow x + \text{FFN}(\text{LN}(x))$ (제18장).
3. 마지막 LayerNorm.
4. 각 은닉 벡터를 어휘 전체에 대한 **로짓**(logits)으로 바꾸는 선형 출력 층. 이 가중치 행렬은 토큰 임베딩 행렬과 공유되며, 이를 **가중치 공유**(weight tying)라고 합니다.

이런 모델의 파라미터 수를 셀 수 있으면 유용합니다. $d$를 은닉 차원, $L$을 층 수, $V$를 어휘 크기라고 합시다. 각 블록에서 어텐션은 $d \times d$ 행렬 네 개($W_Q, W_K, W_V, W_O$)를 가지므로 $4d^2$입니다. 피드포워드 네트워크는 은닉 크기가 $4d$이고 $d \times 4d$ 행렬 두 개를 가지므로 $8d^2$입니다. 작은 편향과 LayerNorm 파라미터를 무시하면 다음을 얻습니다.

$$N \approx 12 L d^2 + V d$$

첫째 항은 트랜스포머 블록, 둘째 항은 임베딩 행렬입니다. 아래 코드는 GPT-2에 대해 정확히 계산합니다.

```python
def gpt_params(vocab, ctx, d, n_layers):
    d_ff = 4 * d                                 # GPT-2의 FFN 은닉 크기
    emb = vocab * d + ctx * d                    # 토큰 임베딩 + 학습되는 위치 임베딩
    attn = 4 * d * d + 4 * d                     # 편향을 포함한 W_Q, W_K, W_V, W_O
    ffn = 2 * d * d_ff + d_ff + d                # 편향을 포함한 선형 층 두 개
    ln = 2 * 2 * d                               # LayerNorm 두 개 (스케일 + 이동)
    final_ln = 2 * d
    # 출력 층은 토큰 임베딩 행렬을 재사용 (가중치 공유)
    return emb + n_layers * (attn + ffn + ln) + final_ln

print(f"GPT-2 small : {gpt_params(50257, 1024, 768, 12) / 1e6:.1f}M")
print(f"GPT-2 medium: {gpt_params(50257, 1024, 1024, 24) / 1e6:.1f}M")
print(f"12*d^2 per block, d=768: {12 * 768**2 / 1e6:.2f}M")
```

출력은 124.4M과 354.8M으로, 가장 작은 두 GPT-2 모델의 잘 알려진 크기입니다. GPT-2 small에서는 임베딩 행렬($50257 \times 768 \approx 38.6$M)이 모델의 거의 3분의 1을 차지한다는 점에 주목하십시오. 아주 큰 모델에서는 $12Ld^2$ 항이 지배적이므로, 대략적인 공식을 흔히 $N \approx 12 L d^2$로 씁니다.

### 루프로서의 생성

디코더 전용 모델은 **자기회귀적으로**(autoregressive generation) 생성합니다. 프롬프트를 읽고, 다음 토큰의 분포를 예측하고, 토큰 하나를 고르고, 그것을 입력에 덧붙인 뒤 반복합니다. 모델이 **시퀀스 종료 토큰**(end-of-sequence token)을 내놓거나 길이 한도에 도달하면 루프가 멈춥니다. 프롬프트와 생성된 토큰을 합친 모든 토큰이 **컨텍스트 창**(context window), 즉 모델이 학습한 최대 시퀀스 길이(GPT-2는 1024 토큰) 안에 들어가야 합니다. 분포에서 토큰을 정확히 어떻게 *고를지*는 제24장의 주제입니다. KV 캐시로 매 단계 접두사 전체를 다시 계산하지 않는 방법은 제36장의 주제입니다.

## 문맥 내 학습

이제 문맥 내 학습을 더 정확히 설명해 봅시다. $k$개의 시연 쌍 $(x_1, y_1), \dots, (x_k, y_k)$와 새 입력 $x$가 있다고 합시다. 이것들을 모두 하나의 텍스트, 즉 **프롬프트**(prompt)에 적고 모델이 이어 쓰게 합니다. 답은 다음 분포에서 생성됩니다.

$$P_\theta(y \mid x_1, y_1, \dots, x_k, y_k, x)$$

여기서 $\theta$는 고정된 사전 학습 파라미터입니다. 경사 하강 단계도 없고 $\theta$의 변화도 없습니다. "학습"은 예시들에 대한 어텐션을 통해 한 번의 순전파 안에서 전부 일어납니다. $k$에 따라 다음과 같이 부릅니다.

- **제로샷**($k = 0$): 지시만 있음. 예: *"Translate English to Russian: book =>"*
- **원샷**(one-shot, $k = 1$): 예시 하나.
- **퓨샷**(few-shot, $k$가 작음, 보통 수십 개까지이며 컨텍스트 창에 의해 제한됨).

문맥 내 학습의 몇 가지 성질은 실무에서 중요합니다.

- **규모에 의존합니다.** GPT-3 실험에서 작은 모델은 예시로부터 얻는 것이 거의 없었지만 가장 큰 모델은 많이 얻었습니다. 일정 규모를 넘어서야 나타나는 능력을 흔히 **창발적 능력**(emergent abilities)이라고 부릅니다. 다만 이런 능력이 정말 갑자기 나타나는지, 아니면 측정 방식 때문에 갑작스러워 보일 뿐인지는 여전히 논의 중입니다(제27장).
- **프롬프트에 민감합니다.** 예시의 순서, 형식, 심지어 레이블 단어의 선택도 정확도를 눈에 띄게 바꿀 수 있습니다. 그래서 프롬프트 설계는 어느 정도 경험적인 기술입니다.
- **모델은 생각보다 형식에 많이 의존합니다.** 실험에 따르면 시연의 레이블을 무작위로 바꾸어도 예상보다 성능이 덜 떨어지는 경우가 있습니다. 예시는 정확한 입력–출력 대응뿐 아니라 *형식*과 *가능한 답의 집합*에 대해서도 모델에게 많은 것을 알려 줍니다.

문맥 내 학습은 도대체 왜 작동할까요? 완전한 답은 없지만 유용한 부분적 설명들이 있습니다. 한 가지 관점에 따르면, 웹에는 목록, 표, 질문–답변 페이지처럼 반복되는 패턴을 가진 텍스트가 많습니다. 따라서 다음 토큰을 잘 예측하려면 앞선 문맥의 패턴을 알아보고 이어 가는 능력이 *반드시* 필요합니다. 해석 가능성 연구는 **유도 헤드**(induction head; Olsson et al., 2022)라는 특정한 어텐션 메커니즘을 찾아냈습니다. 이것은 "앞에서 *A* 다음에 *B*가 왔고 *A*가 다시 나타나면 *B*를 예측하라"는 규칙을 구현합니다. 이 단순한 복사 메커니즘이 더 일반적인 문맥 내 행동의 구성 요소 중 하나입니다. 또 다른 관점은 문맥 내 학습을 암묵적 추론으로 봅니다. 예시가 모델로 하여금 어떤 "과제"나 "문서 유형"이 그 텍스트를 만들었는지 파악하도록 돕고, 모델은 그에 맞게 이어 쓴다는 것입니다.

문맥 내 학습에는 분명한 한계가 있습니다. 예시가 컨텍스트 창을 차지하고, 요청할 때마다 예시를 다시 넣어야 하며, 요청이 끝나면 모델은 아무것도 기억하지 않습니다. 과제를 여러 번 반복해서 쓴다면 미세 조정(제31–33장)이 더 저렴하고 신뢰할 만한 경우가 많습니다. 현대 실무에서는 두 접근을 결합합니다. 먼저 모델을 지시 튜닝하여 제로샷 지시가 잘 작동하게 하고, 필요할 때 프롬프트에 예시를 추가합니다.

## 왜 디코더 전용 모델이 이겼는가

오늘날 대부분의 대형 언어 모델은 디코더 전용입니다. 여러 이유가 함께 작용합니다.

- **모든 과제에 하나의 인터페이스.** 분류, 번역, 코드, 대화 등 어떤 과제든 "텍스트 입력, 텍스트 출력"으로 표현할 수 있습니다. 제22장처럼 과제별 헤드가 필요 없습니다.
- **효율적인 학습 신호.** 인과적 LM은 모든 위치에서 손실을 만듭니다(제21장).
- **잘 확장되는 단순한 아키텍처.** 인코더–디코더 구분 없이 동일한 블록을 쌓은 하나의 스택은 여러 장치에서 병렬로 학습하기 쉽습니다(제28장).
- **효율적인 생성.** 과거 토큰은 미래 토큰에 어텐션하지 않으므로 그 키와 값을 캐시하여 매 단계 재사용할 수 있습니다(제36장).

그 대가는 각 토큰이 왼쪽 문맥만 본다는 것입니다. 실제로 큰 규모에서는 이 제약이 장점들에 비해 훨씬 덜 중요합니다. 제25장에서는 현대 오픈 모델들이 기본 아이디어를 바꾸지 않고 GPT의 방법을 어떻게 다듬었는지 보게 됩니다.

## 요약

- GPT는 트랜스포머 디코더를 인과적 LM으로 사전 학습한 뒤 미세 조정했습니다. GPT-2는 제로샷 과제 전이를, 1,750억 파라미터의 GPT-3는 강력한 퓨샷 문맥 내 학습을 보여 주었습니다.
- 디코더 전용 모델은 인과적 마스크를 쓰는 사전 정규화 트랜스포머 블록의 스택, 마지막 LayerNorm, 그리고 흔히 임베딩과 공유되는 출력 층으로 이루어집니다.
- 파라미터 수는 대략 $12 L d^2 + V d$이며, GPT-2 small은 약 1억 2,400만 개의 파라미터를 가집니다.
- 문맥 내 학습은 가중치를 갱신하지 않고 프롬프트 속 지시와 예시로 과제를 푸는 것, 즉 $P_\theta(y \mid \text{예시}, x)$입니다.
- 문맥 내 학습은 규모와 함께 강해지고, 프롬프트 형식에 민감하며, 유도 헤드 같은 메커니즘으로 부분적으로 설명됩니다.
