## Может ли 100 000 параметров научиться писать?

В главах 16–19 мы изучили трансформер по частям: многоголовое внимание с каузальной маской, информацию о позиции, блок с остаточными связями, нормализацией и FFN, а также архитектуру только с декодировщиком. Теперь соберём всё вместе и зададим конкретный вопрос: может ли модель примерно из 100 000 параметров, обученная 15 секунд на процессоре ноутбука, научиться выдавать русское предложение символ за символом?

Мы построим крошечную модель только с декодировщиком в духе GPT — назовём её **TinyGPT** — примерно в 65 строках на PyTorch. Программа показана ниже в четырёх частях: данные, модель, обучение и генерация. **Поместите четыре блока кода один за другим в один файл**, например `tiny_gpt.py`, и запустите его командой `python tiny_gpt.py`. Нужен только PyTorch; программа работает на CPU. (Если в Windows при печати кириллицы возникает ошибка кодировки, сначала задайте переменную окружения `PYTHONIOENCODING=utf-8`.)

Игрушечная модель специально сделана маленькой, но она не упрощает саму *идею*. Те же части, увеличенные на много порядков, с лучшим токенизатором и гораздо большим объёмом данных, образуют настоящую LLM.

## Шаг 1: данные и посимвольный токенизатор

Чтобы всё было наглядно, мы используем **посимвольный токенизатор** (character-level tokenizer): каждый отдельный символ — это один токен. Как мы видели в главе 3, настоящие модели используют токенизаторы подслов, например BPE. Но посимвольный словарь не требует обучения, и с ним легко увидеть, чему научилась модель. Обучающий текст — два русских предложения, повторённые 20 раз: *«модель читает текст и предсказывает следующий символ»* и *«внимание помогает модели смотреть на прошлые символы»*.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)
text = ("модель читает текст и предсказывает следующий символ. "
        "внимание помогает модели смотреть на прошлые символы. ") * 20
chars = sorted(set(text))                          # посимвольный словарь
stoi = {c: i for i, c in enumerate(chars)}         # символ -> номер
itos = {i: c for c, i in stoi.items()}             # номер -> символ
data = torch.tensor([stoi[c] for c in text])
V, T, D, H, L = len(chars), 32, 64, 4, 2           # словарь, контекст, ширина, головы, слои
```

В **словаре** (vocabulary) $V = 26$ символов: буквы кириллицы, пробел и точка. Весь текст превращается в одномерный тензор `data` из номеров токенов. **Гиперпараметры** (hyperparameters) намеренно крошечные: **контекстное окно** (context window) $T = 32$ символа, ширина модели $D = 64$, $H = 4$ головы (значит, у каждой головы $d_k = 16$) и $L = 2$ блока. Для сравнения: у маленькой GPT-2 ширина 768, 12 голов и 12 блоков.

## Шаг 2: модель

Блок повторяет главу 18 в варианте Pre-Norm: LayerNorm → каузальное многоголовое внимание → остаточная связь, затем LayerNorm → FFN → остаточная связь. Для внимания мы теперь используем встроенную функцию PyTorch `F.scaled_dot_product_attention`. Она вычисляет в точности формулу из главы 16, а флаг `is_causal=True` сам применяет каузальную маску. FFN классическая: скрытая размерность $4D$ и GELU.

```python
class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(D), nn.LayerNorm(D)
        self.qkv, self.proj = nn.Linear(D, 3 * D), nn.Linear(D, D)
        self.ffn = nn.Sequential(nn.Linear(D, 4 * D), nn.GELU(), nn.Linear(4 * D, D))
    def forward(self, x):
        B, t, _ = x.shape
        q, k, v = self.qkv(self.ln1(x)).split(D, dim=-1)
        q, k, v = [z.view(B, t, H, D // H).transpose(1, 2) for z in (q, k, v)]
        y = F.scaled_dot_product_attention(q, k, v, is_causal=True)  # маскированное внимание
        x = x + self.proj(y.transpose(1, 2).reshape(B, t, D))        # остаточная связь 1
        return x + self.ffn(self.ln2(x))                             # остаточная связь 2

class TinyGPT(nn.Module):
    def __init__(self):
        super().__init__()
        self.tok = nn.Embedding(V, D)              # векторные представления токенов
        self.pos = nn.Embedding(T, D)              # обучаемые позиции (глава 17)
        self.blocks = nn.Sequential(*[Block() for _ in range(L)])
        self.ln_f = nn.LayerNorm(D)                # финальная нормализация
        self.head = nn.Linear(D, V, bias=False)    # голова LM: вектор -> логиты
        self.head.weight = self.tok.weight         # связывание весов
        nn.init.normal_(self.tok.weight, std=0.02) # малая инициализация: логиты около 0
    def forward(self, idx):
        x = self.tok(idx) + self.pos(torch.arange(idx.size(1)))
        return self.head(self.ln_f(self.blocks(x)))
```

Полную модель можно читать сверху вниз, как схему в конце главы 18. Номера токенов превращаются в векторы через таблицу векторных представлений (глава 5). К ним прибавляются обучаемые векторы позиций. Два блока обрабатывают последовательность, затем применяется финальная LayerNorm. Наконец, **голова языковой модели** (language model head) — линейный слой размера $D \to V$ — превращает каждый вектор в $V$ **логитов** (logits), то есть ненормированных оценок для следующего токена.

Две детали требуют объяснения.

**Связывание весов.** Матрица головы имеет форму $V \times D$, точно как таблица векторных представлений. Многие модели, включая GPT-2, используют для обеих *одну и ту же* матрицу. Такое **связывание весов** (weight tying) экономит параметры и имеет понятный смысл: логит токена $j$ — это скалярное произведение финального вектора на векторное представление $j$. Значит, модель предсказывает токены, чьи векторы направлены так же, как её выход.

**Инициализация.** PyTorch инициализирует `nn.Embedding` со стандартным отклонением 1. При связывании весов начальные логиты получаются большими, и первая функция потерь равна примерно 45 вместо ожидаемого $\ln V$. Почему $\ln V$? Модель, которая ничего не знает, должна давать каждому токену вероятность $1/V$. Перекрёстная энтропия такой догадки равна $-\ln(1/V) = \ln 26 \approx 3{,}26$. Если заново инициализировать векторные представления с малым стандартным отклонением 0,02, как в GPT-2, мы получим эту разумную стартовую точку. Проверять, что первая функция потерь близка к $\ln V$, — хорошая привычка для любого классификатора.

У модели **103 808 параметров**. В каждом блоке $12\,480$ (QKV) $+ 4\,160$ (выходная проекция) $+ 33\,088$ (FFN) $+ 256$ (две LayerNorm) $= 49\,984$; два блока дают $99\,968$. Таблица позиций добавляет $32 \cdot 64 = 2\,048$, таблица токенов — $26 \cdot 64 = 1\,664$ (она общая с головой), а финальная LayerNorm — $128$.

## Шаг 3: обучение предсказанию следующего токена

Обучение — это цикл из глав 8–10. На каждом шаге мы вырезаем из текста 16 случайных окон по $T + 1$ символу. Первые $T$ символов — это вход `x`; то же окно, сдвинутое на одну позицию, — это цель `y`. Благодаря каузальной маске одно окно даёт сразу $T = 32$ обучающих примера: позиция 0 предсказывает символ 1, позиция 1 предсказывает символ 2 по символам 0–1, и так далее. Функция потерь — **перекрёстная энтропия** (cross-entropy, глава 8) между логитами и настоящими следующими символами, усреднённая по всем $16 \times 32$ позициям. Оптимизатор — AdamW (глава 9).

```python
model = TinyGPT()
opt = torch.optim.AdamW(model.parameters(), lr=3e-3)
print(sum(p.numel() for p in model.parameters()), "parameters")

for step in range(1001):
    ix = torch.randint(len(data) - T - 1, (16,))             # 16 случайных окон
    x = torch.stack([data[i:i + T] for i in ix])
    y = torch.stack([data[i + 1:i + T + 1] for i in ix])     # цели: сдвиг на один
    loss = F.cross_entropy(model(x).view(-1, V), y.view(-1))
    opt.zero_grad()
    loss.backward()
    opt.step()
    if step % 200 == 0:
        print(step, round(loss.item(), 3))
```

На нашем компьютере (PyTorch 2, CPU) вывод был таким:

```
103808 parameters
0 3.27
200 2.955
400 1.439
600 0.398
800 0.109
1000 0.088
```

Точные числа могут немного отличаться в разных версиях PyTorch, но форма кривой поучительна. Она начинается с $3{,}27 \approx \ln 26$ — это равномерная догадка. Затем некоторое время держится около $2{,}95$. Это значение не случайно: энтропия частот символов нашего текста равна $2{,}946$. На этом этапе модель выучила, *какие символы частые* (пробелы, «о», «е»), но ещё не умеет пользоваться контекстом. Это униграммная модель в смысле главы 4. Потом внимание «включается», функция потерь быстро падает, и к шагу 1000 она меньше $0{,}1$: модель правильно предсказывает почти каждый следующий символ. Такие **плато** (plateaus) с последующим резким падением часто встречаются, когда модель должна открыть новый механизм — здесь это способность смотреть назад и копировать.

## Шаг 4: генерация текста

Генерация авторегрессионная, как описано в главе 1. Мы даём модели затравку, берём логиты на **последней** позиции, превращаем их в вероятности с помощью softmax, выбираем один символ путём **сэмплирования** (sampling), добавляем его и повторяем. В таблице позиций всего $T$ строк, поэтому мы подаём не больше последних $T$ символов (`idx[:, -T:]`). Декоратор `@torch.no_grad()` отключает отслеживание градиентов, ведь мы не обучаем модель.

```python
@torch.no_grad()
def generate(prompt, n=60):
    idx = torch.tensor([[stoi[c] for c in prompt]])
    for _ in range(n):
        logits = model(idx[:, -T:])[:, -1, :]                # только последняя позиция
        probs = F.softmax(logits, dim=-1)
        idx = torch.cat([idx, torch.multinomial(probs, 1)], dim=1)
    return "".join(itos[i] for i in idx[0].tolist())

model.eval()
print(generate("модель "))
```

Наш запуск напечатал `модель читает текст и предсказывает следующий символ. внимание помо` — идеальное продолжение. Для сравнения: после всего 300 шагов (функция потерь около 2) тот же код напечатал что-то вроде `модель  пыотелюыемваей и пыом.уыи см.де`. Буквы похожи на русские и встречаются с правильными частотами, но слов нет. Затравка может содержать только символы из словаря; любой другой символ вызовет ошибку `KeyError`.

## Чем TinyGPT отличается от настоящей LLM

Будем честны насчёт того, что мы построили: модель **запомнила** (memorized) два предложения. Текст повторён 20 раз, поэтому обобщать здесь нечего, и мы даже не оставили валидационную выборку (глава 10), чтобы это измерить. Тем не менее архитектура настоящая. Чтобы превратить TinyGPT в модель, подобную моделям из части 5, нужно изменить следующее:

- **Токенизатор:** словарь BPE или SentencePiece из десятков тысяч подслов вместо 26 символов (глава 3).
- **Данные и масштаб:** миллиарды токенов разнообразного текста, а ширина, глубина и число голов — больше на порядки (главы 26–28).
- **Современные компоненты:** RoPE вместо обучаемых позиций (глава 17), RMSNorm и SwiGLU (глава 18), часто внимание с группировкой запросов (глава 25).
- **Детали обучения:** дропаут или другая регуляризация, прогрев и затухание скорости обучения, обрезка градиентов, смешанная точность (главы 10 и 28).
- **Генерация:** температура, сэмплирование top-k и top-p (глава 24) и KV-кэш, чтобы не пересчитывать прошлые ключи и значения (глава 36).

Ни одно из этих изменений не затрагивает основной цикл, который вы только что запустили: векторизовать, применить внимание, преобразовать, предсказать следующий токен, вычислить перекрёстную энтропию, обновить веса. Часть 5 строится именно на этом фундаменте.

## Итоги

- Модель в стиле GPT устроена так: векторные представления токенов + позиции → стек каузальных блоков трансформера → финальная нормализация → линейная голова, выдающая логиты по словарю.
- Благодаря каузальной маске одно окно из $T$ токенов даёт $T$ обучающих примеров предсказания следующего токена; цели равны входу, сдвинутому на один.
- Хорошо инициализированная модель начинает с функции потерь $\approx \ln V$; плато на уровне униграммной энтропии означает, что модель знает частоты символов, но ещё не использует контекст.
- Связывание весов делает матрицу векторных представлений общей с выходной головой и экономит параметры.
- При генерации модель многократно получает последние $T$ токенов, выбирает символ из softmax на последней позиции и добавляет результат.
