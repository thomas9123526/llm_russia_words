# 제30장. 다국어 모델과 교차 언어 전이

> **제6부 — 대규모 학습** · 수준: 고급
>
> **이 장에서 배울 내용:** 하나의 모델이 공유 어휘와 혼합 말뭉치로 어떻게 여러 언어를 배우는가 · 러시아어와 한국어 텍스트의 토큰화가 왜 영어보다 비싸며, 온도 샘플링은 언어 간 균형을 어떻게 맞추는가 · 교차 언어 전이란 무엇이며, 왜 작동하고, 어디에서 한계에 부딪히는가

처음 이 실험을 했을 때 연구자들은 놀랐습니다. 다국어 모델을 하나 가져와 **영어 예제만으로** 영화 리뷰의 감성을 분류하도록 미세 조정(fine-tuning)한 다음, 한 번도 미세 조정에 쓰지 않은 언어로 된 처음 보는 리뷰 두 개를 줍니다.

- «Фильм был потрясающим, я смотрел его два раза.» (러시아어: "영화가 굉장했어요. 두 번 봤어요.")
- «영화가 너무 지루해서 중간에 나왔다.»

모델은 첫 번째를 긍정, 두 번째를 부정으로 분류하는데, 그 빈도가 우연으로 설명할 수 있는 수준보다 훨씬 높습니다. 러시아어나 한국어 레이블은 하나도 쓰지 않았습니다. 이것이 **교차 언어 전이(cross-lingual transfer)** 이며, 이 장의 중심 현상입니다. 한국어, 영어, 러시아어로 읽는 연구자인 여러분에게는 실용적인 질문이기도 합니다. LLM은 여러분의 언어에서 실제로 얼마나 잘 작동하며, 그 이유는 무엇일까요?

## 하나의 모델, 여러 언어

**다국어 모델(multilingual model)** 은 평소와 같은 방식, 즉 마스크 언어 모델링이나 인과 언어 모델링(제21장)으로 학습합니다. 다만 여러 언어가 섞인 말뭉치를 하나의 공유 토크나이저와 어휘로 사용합니다. 사전이나 병렬 텍스트는 필요하지 않습니다.

처음으로 널리 연구된 예는 **다국어 BERT(mBERT)** 입니다. 제22장의 BERT 아키텍처를 약 100개 언어의 위키백과로, 공유 WordPiece 어휘를 써서 학습한 것입니다. **XLM**(Lample, Conneau, 2019)은 병렬 문장 쌍에 대한 학습 목표인 *번역 언어 모델링*을 추가했습니다. 여기서는 마스크된 단어를 두 언어 중 어느 쪽의 문맥으로든 예측할 수 있습니다. **XLM-R**(Conneau 등, 2020)은 단순한 마스크 언어 모델링으로 돌아갔지만 훨씬 많은 데이터를 사용했습니다. 제26장에서 설명한 종류의 파이프라인으로 준비한 100개 언어의 필터링된 Common Crawl 텍스트와 토큰 25만 개짜리 SentencePiece 어휘(제3장)입니다. mT5 같은 인코더–디코더 모델과 많은 디코더 전용 LLM도 같은 취지로 여러 언어에 걸쳐 학습됩니다.

데이터는 매우 불균형합니다. 웹에서 영어는 압도적으로 가장 큰 언어이고, 러시아어는 큰 언어들 중 하나이며, 한국어 텍스트는 훨씬 적고, 세계의 많은 언어는 텍스트가 거의 없습니다. 이 분야의 용어로 **고자원 언어(high-resource language)** 와 **저자원 언어(low-resource language)** 가 있으며, 그 차이는 몇 자릿수에 이릅니다.

## 서로 다른 문자에서의 토큰화

언어들이 처음으로 불평등하게 다루어지는 곳은 토크나이저입니다. 언어마다 서로 다른 **문자 체계(writing system)** 를 씁니다. 제2장에서 보았듯 UTF-8은 라틴 문자에 1바이트, 키릴 문자에 2바이트, 한글 음절에 3바이트를 씁니다. 주로 영어로 학습한 바이트 수준 토크나이저는 영어에 대해서는 병합을 많이 배웠지만 다른 문자에 대해서는 상대적으로 적게 배웠습니다.

```python
import numpy as np

sentences = {
    "en": "The model learns language from data.",
    "ru": "Модель изучает язык по данным.",
    "ko": "모델은 데이터로부터 언어를 배운다.",
}
for lang, s in sentences.items():
    n_bytes = len(s.encode("utf-8"))
    print(f"{lang}: {len(s.split())} words, {len(s)} chars, {n_bytes} UTF-8 bytes, "
          f"{n_bytes / len(s):.2f} bytes/char")

# 언어별 온도 샘플링: p_i ∝ (n_i / N) ** alpha
sizes = np.array([1000.0, 100.0, 20.0])     # 데이터 양(예: GB): en, ru, ko
q = sizes / sizes.sum()                     # 자연 비율
for alpha in [1.0, 0.5, 0.3]:
    p = q**alpha / (q**alpha).sum()
    print(f"alpha={alpha}: en={p[0]:.2f}, ru={p[1]:.2f}, ko={p[2]:.2f}")
```

첫 번째 부분의 출력은 다음과 같습니다.

```text
en: 6 words, 36 chars, 36 UTF-8 bytes, 1.00 bytes/char
ru: 5 words, 30 chars, 55 UTF-8 bytes, 1.83 bytes/char
ko: 4 words, 19 chars, 49 UTF-8 bytes, 2.58 bytes/char
```

같은 의미가 영어로는 36바이트, 러시아어로는 55바이트, 한국어로는 49바이트입니다. (러시아어가 문자당 2바이트보다 적은 것은 공백과 마침표가 각각 1바이트이기 때문입니다.) 키릴 문자와 한글에 대한 좋은 병합을 배우지 못한 토크나이저는 이 바이트들을 훨씬 많은 토큰으로 바꿉니다.

이를 재는 표준 척도는 **토크나이저 생산성(tokenizer fertility)**, 즉 단어당 평균 토큰 수입니다. 생산성이 높으면 세 가지 비용이 생깁니다. 같은 텍스트에 연산이 더 들고, 같은 문맥 창(제17장)에 텍스트가 덜 들어가며, 모델이 더 많고 더 작은 조각들로부터 의미를 조립해야 하므로 대개 품질이 떨어집니다.

형태론은 문제를 더 키웁니다. 러시아어는 **형태론적으로 풍부한 언어(morphologically rich language)** 입니다. 명사 하나에 여러 형태가 있습니다. «книга, книги, книге, книгу, книгой, о книге»(격에 따른 "책"의 형태)가 그 예입니다. 한국어는 **교착어**입니다. 조사와 어미가 어간에 붙습니다. «학교», «학교에», «학교에서», «학교에서는», «학교에서만»처럼요. 그래서 두 언어 모두 띄어쓰기로 구분된 "단어"가 길며, 좋은 토크나이저라면 이를 임의로가 아니라 의미 있는 조각(어간 + 어미, 또는 체언 + 조사)으로 나누어야 합니다. 한국어에는 선택지가 하나 더 있습니다. 한글 음절 블록은 자모로 이루어져 있으므로 «한»을 문자 하나로 둘 수도 있고 ㅎ, ㅏ, ㄴ으로 분해할 수도 있습니다. 각 언어가 어휘 항목을 몇 개나 받는지, 즉 **어휘 할당(vocabulary allocation)** 은 다국어 모델의 실제 설계 결정입니다.

## 학습에서 언어 간 균형 맞추기

가용 데이터에 비례하여 학습 문서를 뽑으면 모델은 거의 영어만 보게 됩니다. 모든 언어를 똑같이 뽑으면 작은 언어들이 여러 번 반복되어 과적합됩니다(제27장, 데이터 제약 스케일링). 흔한 절충안은 **온도 샘플링(temperature sampling)** 입니다. 언어 $i$의 데이터 양을 $n_i$라 하고, 그 자연 비율을 $q_i = n_i / \sum_j n_j$라고 합시다. 언어 $i$를 다음 확률로 뽑습니다.

$$
p_i = \frac{q_i^{\alpha}}{\sum_j q_j^{\alpha}}, \qquad 0 < \alpha \le 1 .
$$

$\alpha = 1$이면 자연 비율이 그대로 유지되고, $\alpha \to 0$이면 분포가 균등해집니다. 코드의 두 번째 부분은 영어, 러시아어, 한국어가 각각 1000, 100, 20단위인 가상의 말뭉치에 대한 효과를 보여 줍니다.

```text
alpha=1.0: en=0.89, ru=0.09, ko=0.02
alpha=0.5: en=0.69, ru=0.22, ko=0.10
alpha=0.3: en=0.55, ru=0.28, ko=0.17
```

$\alpha = 0.3$에서 한국어는 자연 비율보다 약 9.6배 자주 뽑힙니다($20/1120 \approx 0.018$ 대신 $0.17$). 잘 알려진 다국어 모델들에서는 대략 0.3에서 0.7 사이의 $\alpha$ 값이 사용되었습니다.

그렇다면 언어를 계속 더 추가하면 왜 안 될까요? Conneau 등(2020)은 **다국어성의 저주(curse of multilinguality)** 를 설명했습니다. 모델 크기가 고정되어 있을 때 언어를 추가하면 처음에는 전이를 통해 저자원 언어에 도움이 되지만, 어느 지점을 넘으면 모든 언어의 성능이 떨어지기 시작합니다. 언어들이 같은 한정된 용량을 두고 경쟁하기 때문입니다. 이런 경쟁을 부정적 간섭이라고 합니다. 해법은 용량을 늘리는 것입니다. 더 큰 모델을 쓰거나, 예컨대 MoE 모델(제29장)의 언어별 전문가처럼 언어당 매개변수를 늘리는 것입니다.

## 교차 언어 전이

이 장 첫머리의 실험으로 돌아가 봅시다. **제로샷 교차 언어 전이(zero-shot cross-lingual transfer)** 란 한 언어(레이블을 얻기 쉬운 영어가 보통입니다)로 어떤 작업에 미세 조정한 뒤, 다른 언어들에서 곧바로 평가하는 것을 말합니다. XNLI(15개 언어의 자연어 추론) 같은 벤치마크가 이를 측정하기 위해 만들어졌습니다.

왜 이것이 작동할까요? 여러 요인이 기여합니다.

- **공유 토큰.** 숫자, 이름, URL, 코드, 많은 외래어는 언어가 달라도 비슷해 보입니다. «компьютер», «컴퓨터», "computer"는 세 가지 문자로 쓴 같은 단어이고, «интернет»와 «인터넷»도 마찬가지입니다. mBERT의 성공에 대한 초기 설명은 이런 공유 조각을 지목했습니다. 같은 이유로, 언어 간 겹침을 늘리기 위해 러시아어를 라틴 문자로 적는 것처럼 공통 문자로 **음역(transliteration)** 하는 방법도 사용되었습니다.
- **공유 구조.** 이후 연구들은 공유 하위 단어가 전혀 없는 언어들 사이에서도 전이가 일어나며, 모델의 깊이가 더 중요하다는 것을 발견했습니다. 모델은 서로 다른 언어가 비슷한 문맥에서 비슷한 의미를 표현한다는 것을 발견하고, 같은 내부 특징을 재사용하는 듯합니다.
- **정렬된 표현.** 어떤 문장과 그 번역문의 은닉 벡터를 계산하면, 특히 중간 층에서 서로 가까운 경우가 많습니다. 사실상 모델은 부분적으로 언어 중립적인 의미 공간을 만들어 내며, 영어 벡터 위에서 학습한 분류기가 러시아어와 한국어 벡터에서도 작동합니다. 이를 **교차 언어 정렬(cross-lingual alignment)** 이라고 합니다.

전이는 모든 언어 쌍에서 똑같지 않습니다. 보통 문자와 어순을 공유하는 친족 언어들 사이에서 가장 잘 작동하고, 먼 언어들 사이에서는 약합니다. 러시아어와 한국어는 서로 다른 방식으로 영어와 멉니다. 러시아어는 다른 문자를 쓰고, 어순이 자유로우며, 격 형태론이 풍부합니다. 한국어는 다른 문자를 쓰고, 동사를 끝에 두며(주어–목적어–동사 어순), 문법을 조사로 표현합니다. 제로샷 전이로 충분하지 않을 때 흔히 쓰는 대안은 *translate-train*(영어 학습 데이터를 목표 언어로 기계 번역)과 *translate-test*(테스트 입력을 영어로 번역)입니다. 목표 언어로 레이블된 예제가 조금만 있어도 대개 크게 도움이 됩니다.

실제 사용자는 한 메시지 안에서 언어를 섞기도 합니다. 이것이 **코드 전환(code-switching)** 으로, «Мне нужно сделать fine-tuning модели»나 «이 모델은 inference가 느려요» 같은 예가 있습니다. 다국어 모델은 단일 언어 모델보다 이를 잘 처리하지만, 여전히 오류의 원천입니다.

여러분의 연구를 위해 두 가지를 더 짚어 둡니다. 첫째, 여러분의 두 언어 모두에 전용 모델과 벤치마크가 있습니다. 예를 들어 러시아어에는 Russian SuperGLUE, 한국어에는 KLUE가 있고, 주로 러시아어나 한국어 텍스트로 학습한 BERT 및 GPT 방식의 모델들도 있습니다. 이들을 다국어 모델과 비교하는 것은 고전적인 연구 설계입니다. 둘째, 영어 중심의 공개 모델을 러시아어나 한국어에 맞게 개선하는 흔한 방법은 목표 언어 텍스트로 **계속 사전 학습(continued pre-training)** 하는 것이며, 생산성을 낮추기 위해 어휘를 확장하기도 합니다. 관련된 적응 방법은 제7부에서 보게 됩니다. 마지막으로 **문화적 편향(cultural bias)** 을 기억하십시오. 한국어를 유창하게 구사하는 모델이라도 영어권 출처에서 가져온 전제로 추론할 수 있습니다.

## 요약

- 다국어 모델은 하나의 공유 어휘를 쓰는 혼합 말뭉치에서 평범한 언어 모델링으로 학습됩니다(mBERT, XLM, XLM-R, mT5, 다국어 LLM). 병렬 데이터는 도움이 되지만 필수는 아닙니다.
- UTF-8과 영어 중심 토크나이저는 러시아어(키릴 문자, 풍부한 굴절)와 한국어(한글, 교착)를 더 비싸게 만들며, 토크나이저 생산성이 이 비용을 측정합니다.
- 온도 샘플링 $p_i \propto q_i^\alpha$는 저자원 언어의 비율을 높입니다. 다국어성의 저주는 언어들이 고정된 용량을 두고 경쟁한다는 것을 보여 줍니다.
- 제로샷 교차 언어 전이는 공유 토큰, 공유 구조, 부분적으로 정렬된 표현 덕분에 작동하며, 유형론적으로 먼 언어들에서는 약해집니다.
- translate-train, translate-test, 소량의 목표 언어 레이블, 어휘 확장을 동반한 계속 사전 학습은 특정 언어의 결과를 개선하는 실용적인 방법입니다.

## 연습 문제

1. 영어 데이터만으로 미세 조정한 감성 분류기가 러시아어와 한국어 리뷰에서 작동할 수 있는 이유를 자신의 말로 설명하십시오.
2. $p_i$ 공식을 사용하여 데이터 양이 500(영어), 50(러시아어), 5(한국어)이고 $\alpha = 0.5$일 때의 샘플링 확률을 계산하십시오. 한국어는 자연 비율보다 몇 배 자주 뽑힙니까?
3. 각 언어로 직접 고른 문장 세 개씩(예: 이 장의 러시아어판과 한국어판에서)을 코드에 추가하십시오. 문자당, 단어당 평균 바이트 수를 계산하십시오. 바이트 기준으로 "단어"가 가장 긴 언어는 무엇이며, 그 이유는 무엇입니까?
4. 원하는 러시아어 명사 하나의 여섯 가지 격 형태와, 서로 다른 조사 다섯 개를 붙인 «학교»의 형태를 적어 보십시오. 이상적인 토크나이저라면 이들을 어떻게 나누기를 바랍니까?
