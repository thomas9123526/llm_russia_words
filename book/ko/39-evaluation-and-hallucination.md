## 모델 B가 정말 더 나은가?

모델 A는 벤치마크 문제의 70%를, 모델 B는 72%를 맞힙니다. 벤치마크에는 1,000문제가 있습니다. B가 더 나은 모델일까요?

각 문제를 모델이 확률 $p$로 맞히는 동전 던지기로 간주하겠습니다. 측정된 정확도의 **표준 오차(standard error)** 는 다음과 같습니다.

$$
\text{SE} = \sqrt{\frac{p(1-p)}{n}}
$$

여기서 $n$은 문제 수입니다. $p = 0.7$, $n = 1000$이면 $\text{SE} = \sqrt{0.21 / 1000} \approx 0.0145$입니다. 95% 신뢰 구간은 약 $\pm 1.96 \cdot \text{SE} \approx \pm 2.8$퍼센트포인트입니다. A와 B의 2포인트 차이는 완전히 잡음 범위 안에 있습니다. (두 모델이 같은 문제에 답하므로 대응 검정이 더 민감하지만, 교훈은 그대로입니다.) 발표된 "개선" 가운데 상당수가 이 정도 크기입니다.

이 작은 예가 이 장의 정신을 보여 줍니다. **평가(evaluation)** 는 쉬워 보입니다. 모델을 돌리고 맞힌 답을 세면 됩니다. 하지만 거의 모든 단계에 선택이 숨어 있습니다. 무엇을 측정할지, 어떤 데이터로 할지, 어떤 프롬프트를 쓸지, 자유 텍스트를 어떻게 채점할지, 그리고 결과를 얼마나 확신할 수 있는지. 이 분야의 박사 과정에서는 이런 질문에 많은 시간을 쓰게 됩니다. 방법은 그 뒤에 있는 평가만큼만 설득력이 있기 때문입니다.

자동 지표에서 시작해 벤치마크로, 다음으로 사람과 모델 심판으로 나아가고, 마지막으로 LLM의 가장 눈에 띄는 실패인 환각을 다룹니다.

## 자동 지표

가장 기본적인 내재적 지표는 제4장에서 이미 만났습니다. **퍼플렉서티(perplexity)** 는 토큰당 평균 음의 로그 우도의 지수입니다. 모델이 텍스트를 얼마나 잘 예측하는지 알려 주고, 계산 비용이 싸며, 사전 학습 중에 *같은 토크나이저*를 쓰는 모델을 비교하는 데 유용합니다. 하지만 모델이 쓸모 있는지에 대해서는 거의 알려 주지 않으며, 토크나이저가 다르면 비교할 수 없습니다. 러시아어 단어를 더 많은 토큰으로 쪼개는 모델은 토큰당 예측 과제가 더 쉬워지기 때문입니다(제30장).

과제에서는 모델의 출력을 참조 답과 비교합니다.

- 객관식 문제에는 **정확도(accuracy)**: 올바른 선택의 비율입니다.
- 짧은 답에는 **정확 일치(exact match, EM)**: 정규화(소문자화, 문장 부호 제거) 후 예측이 참조 답과 똑같은지 봅니다.
- **토큰 F1(F1 score)**: 부분 점수를 주는 더 부드러운 버전입니다. **정밀도(precision)** $P$ = 공통 토큰 / 예측 토큰, **재현율(recall)** $R$ = 공통 토큰 / 참조 토큰일 때 $F_1 = 2PR/(P+R)$입니다.
- 번역과 요약에는 **BLEU** 와 **ROUGE**: 하나 이상의 참조와의 n-그램 겹침입니다. 사람의 판단과는 중간 정도로만 상관되며, 올바른 번역이 다른 어형을 쓸 수 있는 러시아어 같은 형태론적으로 풍부한 언어에서 특히 그렇습니다.
- 코드에는 **pass@k**: 프로그램을 $k$개 생성하고, 하나라도 단위 테스트를 통과하면 문제를 푼 것으로 칩니다.

pass@k의 단순한 추정(정확히 $k$개를 한 번 생성)은 분산이 큽니다. Chen et al.(2021)은 $n \geq k$개를 생성해 정답 $c$개를 센 뒤, 무작위로 뽑은 $k$개 부분집합에 정답 프로그램이 적어도 하나 있을 확률을 계산하자고 제안했습니다.

$$
\text{pass@}k = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}
$$

아래 코드는 이 지표들을 구현합니다.

```python
from collections import Counter
from math import comb

def normalize(s):
    return s.lower().replace(".", "").replace(",", "").split()

def exact_match(pred, gold):
    return float(normalize(pred) == normalize(gold))

def token_f1(pred, gold):
    p, g = normalize(pred), normalize(gold)
    overlap = sum((Counter(p) & Counter(g)).values())   # 공통 토큰
    if overlap == 0:
        return 0.0
    precision, recall = overlap / len(p), overlap / len(g)
    return 2 * precision * recall / (precision + recall)

def pass_at_k(n, c, k):
    """비편향 pass@k: 생성한 샘플 n개 중 c개가 정답."""
    if n - c < k:
        return 1.0
    return 1.0 - comb(n - c, k) / comb(n, k)

print(exact_match("Moscow.", "moscow"))                      # 1.0
print(round(token_f1("the city of Moscow", "Moscow"), 3))    # 0.4
print(round(pass_at_k(10, 3, 1), 4), round(pass_at_k(10, 3, 5), 4))  # 0.3 0.9167
```

F1 예에서는 예측 토큰 네 개 중 하나가 공통이므로 $P = 0.25$, $R = 1$, $F_1 = 0.5 / 1.25 = 0.4$입니다. $n = 10$, $c = 3$인 pass@k에서 pass@1은 그냥 $3/10$이고, pass@5 $= 1 - \binom{7}{5}/\binom{10}{5} = 1 - 21/252 \approx 0.917$입니다.

## 벤치마크와 그 함정

**벤치마크(benchmark)** 는 여러 모델을 비교할 수 있도록 고정된 지표를 갖춘 고정된 데이터셋입니다. 잘 알려진 예로 MMLU(수십 개 학문 분야에 걸친 객관식 문제), GSM8K(초등 수준 수학 서술형 문제), HumanEval(단위 테스트로 검사하는 Python 함수), HellaSwag(상식 기반 문장 완성), TruthfulQA(사람들이 흔히 잘못 믿는 내용에 관한 질문)가 있습니다. 러시아어에는 여러 과제를 하나의 점수로 묶은 Russian SuperGLUE와 MERA 같은 모음이 있고, 영어 벤치마크를 여러 언어로 번역한 다국어 세트도 있습니다. 벤치마크는 없어서는 안 되지만 잘 알려진 함정이 있습니다.

- **오염.** 벤치마크 문제는 인터넷에 공개되고, 인터넷이 곧 학습 데이터입니다(제26장). 모델이 테스트 세트를 보았다면 그 점수는 능력이 아니라 기억을 측정합니다. **데이터 누출(data leakage)** 의 한 형태인 이런 **벤치마크 오염(benchmark contamination)** 은 학습 데이터가 공개되지 않은 모델에서는 배제하기 어렵습니다. 연구자들은 학습 데이터와의 n-그램 겹침을 확인하거나, 오래된 문제와 새로 작성한 문제에서의 성능을 비교하거나, 비공개 **홀드아웃 세트(held-out set)** 를 유지합니다.
- **포화.** 최상위 모델들이 거의 만점에 이르면 벤치마크는 더 이상 모델을 구별하지 못하며, 남은 오류 중 일부는 데이터셋 자체의 라벨 오류인 경우가 많습니다.
- **프롬프트 민감도.** 점수는 프롬프트 형식, 퓨샷 예시 수, 답을 추출하는 방식에 따라 몇 포인트씩 바뀔 수 있습니다. 비교는 설정이 동일할 때만 공정합니다.
- **굿하트의 법칙.** "측정치가 목표가 되면 더 이상 좋은 측정치가 아니다." **리더보드(leaderboard)** 를 겨냥해 최적화하면 모델은 나아지지 않고 숫자만 나아질 수 있습니다.

글쓰기나 대화 같은 개방형 과제에는 하나의 정답이 없습니다. 이때의 표준은 **인간 평가(human evaluation)** 이며, 흔히 쌍대 비교 방식입니다. 사람이 같은 프롬프트에 대한 두 답을 보고 더 나은 쪽을 고릅니다. 이런 투표를 많이 모으면 **Elo 레이팅(Elo rating)** 이나 Bradley–Terry 모델로 순위를 만들 수 있습니다. 이 모델에서 모델 $i$가 모델 $j$를 이길 확률은 다음과 같습니다.

$$
P(i \succ j) = \frac{1}{1 + 10^{(R_j - R_i)/400}}
$$

여기서 $R_i, R_j$는 모델의 레이팅입니다. 100점 차이는 더 강한 모델이 비교의 약 64%에서 이긴다는 뜻입니다. 인간 평가는 느리고 비싸며 사람들끼리도 의견이 갈리므로 **평가자 간 일치도(inter-annotator agreement)** 를 보고해야 합니다.

더 싼 대안은 **심판으로서의 LLM(LLM-as-a-judge)** 입니다. 강한 모델이 답을 비교하거나 채점합니다. Zheng et al.(2023)은 이런 심판이 사람들끼리 일치하는 만큼 자주 사람과 일치한다는 것을 발견했지만, 뚜렷한 편향도 기록했습니다. 첫 번째나 두 번째 답을 선호하는 **위치 편향(position bias)**, 더 긴 답을 선호하는 **장황함 편향(verbosity bias)**, 자신의 문체로 된 답을 선호하는 **자기 선호(self-preference)** 입니다. 표준적인 예방책은 두 순서로 모두 평가하고, 길이를 통제하며, 표본에서 사람의 라벨로 심판을 검증하는 것입니다.

## 환각

**환각(hallucination)** 은 유창하고 자신감 있지만 사실이나 주어진 출처로 뒷받침되지 않는 생성 내용입니다. 좁은 주제에 대한 참고 문헌을 요청하면 모델은 존재하지 않는 논문에 대한 완벽한 형식의 인용을 만들어 낼 수 있습니다. 다음을 구별하면 유용합니다.

- **사실성(factuality)** 오류: 진술이 세상에 대한 지식과 모순됩니다("모스크바는 볼가강 변에 있다").
- **충실성(faithfulness)** 오류: 출력이 주어진 입력과 모순되거나 입력에 없는 것을 덧붙입니다. 예를 들어 요약이 문서에 없는 숫자를 언급하는 경우입니다. 이는 RAG(제37장)에서 특히 중요합니다.

모델은 왜 환각을 일으킬까요? 사전 학습 목표(제21장)는 참인 연속이 아니라 가장 그럴듯한 연속을 보상하는데, 그럴듯한 저자 이름과 연도는 바로 인용 형식의 패턴에 들어맞습니다. 학습에서 드물게 나온 사실은 가중치에 약하게 저장됩니다. 지시 튜닝과 RLHF(제33–34장)는 도움이 되고 자신감 있게 들리는 답을 보상할 수 있으며, "모르겠습니다"에 0점을 주는 평가도 같은 방향으로 밀어붙입니다. 높은 온도의 샘플링(제24장)은 모델을 자신이 아는 것에서 더 멀어지게 할 수 있습니다.

정답을 모르는 상태에서 어떻게 환각을 탐지할 수 있을까요?

- **일관성.** 같은 질문에 대해 답을 여러 개 샘플링합니다. 모델이 사실을 알면 답들이 일치하고, 추측하고 있으면 흩어집니다. SelfCheckGPT(Manakul et al., 2023)는 이 아이디어에 기반합니다. **의미 엔트로피(semantic entropy)**(Farquhar et al., 2024)는 이를 다듬은 것입니다. 샘플링한 답을 의미에 따라 묶고("Moscow"와 "the city of Moscow"는 하나로 셉니다) 묶음에 대한 엔트로피를 계산합니다. 엔트로피가 높으면 작화(confabulation)일 가능성이 큽니다.
- **검증.** 답을 원자적 주장으로 쪼개 각 주장을 검색된 출처와 대조합니다. 여러 사실성 지표가 이 접근법에 바탕을 둡니다.
- **보정(calibration).** 모델이 80% 확신으로 내놓은 답들 가운데 약 80%가 맞는다면 그 모델은 **보정되어** 있다고 합니다. **기대 보정 오차(expected calibration error)** 는 예측을 확신도 구간 $B_b$로 나누고 차이를 평균합니다.

$$
\text{ECE} = \sum_{b} \frac{|B_b|}{n} \left| \text{acc}(B_b) - \text{conf}(B_b) \right|
$$

여기서 $|B_b|$는 구간 $b$에 속한 예측 수, $n$은 전체 예측 수, $\text{acc}$는 구간 안의 정확도, $\text{conf}$는 평균 확신도입니다. 잘 보정된 모델이라면 "확실하지 않습니다"라는 말을 믿을 수 있고, 이것이 확신이 낮을 때 답을 거부하는 **기권(abstention)** 의 바탕이 됩니다.

완화책은 여러 도구를 조합합니다. 검색된 출처와 인용에 답을 근거시키기, 기권하도록 모델 학습시키기, 사실 관련 과제에서 보수적으로 디코딩하기, 나중에 주장을 검증하기입니다. 그 어느 것도 환각을 완전히 없애지는 못하며, 그래서 환각은 제40장에서 논의할 핵심적인 열린 문제 중 하나로 남아 있습니다.

## 요약

- 항상 불확실성을 추정하세요. 테스트 항목이 $n$개일 때 정확도의 표준 오차는 $\sqrt{p(1-p)/n}$이므로, 모델 간 작은 차이는 잡음인 경우가 많습니다.
- 퍼플렉서티는 예측 품질을 측정합니다. 과제 지표로는 정확도, 정확 일치, 토큰 F1, BLEU/ROUGE, 코드용 비편향 pass@k가 있습니다.
- 벤치마크는 오염, 포화, 프롬프트 민감도, 굿하트의 법칙에 시달립니다. 홀드아웃 세트와 새로 작성한 테스트 세트가 도움이 됩니다.
- Elo나 Bradley–Terry로 집계한 사람의 쌍대 판단이 개방형 과제의 표준입니다. LLM 심판은 더 싸지만 위치, 장황함, 자기 선호 편향이 있습니다.
- 환각은 유창하지만 근거 없는 출력입니다. 일관성 검사, 의미 엔트로피, 주장 검증, 보정으로 탐지할 수 있으며, 근거 제시와 기권으로 줄일 수는 있지만 없앨 수는 없습니다.
