>
> **이 장에서 배울 내용:** 사전 학습용 텍스트는 어디에서 오며 어떻게 추출하는가 · 휴리스틱 필터와 모델 기반 필터는 무엇을 "좋은" 텍스트로 판단하는가 · MinHash와 LSH는 수십억 개의 문서에서 어떻게 유사 중복을 찾아내는가

아무 웹 페이지나 열어서 언어 모델의 눈으로 바라봅시다. 기사 옆에는 내비게이션 메뉴, 쿠키 배너, "관련 게시물" 목록, 저작권 문구, 때로는 검색 엔진용 키워드 블록이 있습니다. 웹의 다른 곳에는 같은 기사가 매번 다른 메뉴에 둘러싸인 채 백 번쯤 복사되어 있습니다. 이 모든 것을 그대로 모델에 넣으면 연산 예산의 상당 부분이 메뉴를 배우고 복사본을 암기하는 데 쓰입니다.

제5부에서 우리는 학습 **말뭉치(corpus)** 를 "수조 개의 토큰으로 된 텍스트"라는 주어진 것으로 다루었습니다. 이 장에서는 그 상자를 열어 봅니다. 데이터의 품질은 적어도 아키텍처만큼 중요하며, 현대의 사전 학습 프로젝트에서 작업의 대부분은 데이터 작업입니다.

## 텍스트는 어디에서 오는가

사전 학습 말뭉치는 보통 여러 출처의 **혼합**입니다.

- **웹 크롤링 결과.** 단연 가장 큰 출처입니다. 공개 프로젝트인 Common Crawl은 여러 해에 걸쳐 수십억 개 웹 페이지의 스냅숏을 모아 왔고, 대부분의 공개 말뭉치(C4, The Pile의 웹 부분, RefinedWeb, FineWeb 등)가 여기에서 출발합니다.
- **책과 긴 문서.** 먼 거리에 걸친 일관성을 가르쳐 줍니다.
- **백과사전.** 예를 들어 위키백과는 깨끗하고 사실 중심적이며 많은 언어로 제공됩니다.
- **과학 논문**(예: arXiv)과 **코드**(공개 저장소). 코드는 이제 표준 재료가 되었습니다. 프로그래밍뿐 아니라 구조화된 추론에도 도움이 되는 것으로 보이기 때문입니다.
- **대화와 포럼.** 질문, 답변, 비격식 언어가 담겨 있습니다.

**웹 크롤링(web crawling)** 의 원시 결과는 HTML로 저장됩니다. 첫 단계는 **텍스트 추출(text extraction)**, 즉 HTML을 일반 텍스트로 바꾸고 메뉴, 푸터, 버튼, 광고 같은 **상용구 제거(boilerplate removal)** 를 하는 것입니다. 이를 위한 도구는 페이지 구조에 관한 규칙을 사용합니다. 예를 들어 긴 텍스트 문단은 본문일 가능성이 높고, 링크가 많은 짧은 블록은 내비게이션일 가능성이 높습니다. 추출 품질은 생각보다 중요합니다. 부주의한 추출기는 말뭉치에 "쿠키 허용" 같은 줄을 수천 번 남겨 둡니다.

두 번째 단계는 **언어 식별(language identification)** 입니다. 작고 빠른 분류기(문자 n-그램 위의 fastText 방식 모델이 전형적입니다)가 각 문서의 언어와 신뢰도 점수를 예측합니다. 말뭉치는 이렇게 영어, 러시아어, 한국어 등의 부분으로 나뉩니다. 이 주제는 제30장에서 다시 다룹니다.

마지막으로 출처들을 정해진 가중치로 합칩니다. 이 **데이터 혼합(data mixing)** 은 설계상의 결정입니다. 예를 들어 코드가 토큰의 일정 비율을 차지하도록 하고, 웹은 한 번만 보는 반면 위키백과는 여러 번 보도록 정할 수 있습니다. 하나의 정답 레시피는 없으며, 혼합 비율은 제27장의 스케일링 방법을 이용한 소규모 실험으로 조정합니다.

## 정제와 품질 필터링

추출을 마친 뒤에도 웹 텍스트의 대부분은 모델이 흉내 내기를 바라는 글이 아닙니다. 필터링은 크게 두 가지 방식으로 이루어집니다.

**휴리스틱 필터(heuristic filter)** 는 각 문서에 대해 계산하는 단순한 규칙입니다. C4와 Gopher 말뭉치에서 사용된 규칙과 비슷한 전형적인 예는 다음과 같습니다.

- 문서의 단어 수가 너무 적거나 터무니없이 깁니다.
- 평균 단어 길이가 정상 범위를 벗어납니다.
- 문장 부호 없이 끝나는 줄이나 글머리 기호로 시작하는 줄의 비율이 너무 높습니다.
- `#`이나 `{` 같은 기호가 차지하는 문자 비율이 너무 높습니다.
- 문서 안에서 많은 줄이나 문단이 반복됩니다.
- 해당 언어에서 가장 흔한 기능어(영어의 "the", "and", "of")가 거의 없습니다. 이는 산문이 아니라 키워드 목록이라는 신호입니다.

각 규칙은 저렴하고 투명하며 조정하기 쉽습니다. 이 규칙들을 함께 적용하면 크롤링 결과의 상당 부분이 제거됩니다.

**모델 기반 필터**는 좋은 텍스트가 어떤 모습인지를 학습합니다. 한 가지 방법은 고품질 텍스트의 기준 집합(예: 위키백과 또는 위키백과가 링크하는 페이지)과 무작위 웹 텍스트를 구별하는 분류기를 학습시키고, 점수가 높은 문서를 남기는 것입니다. CCNet에서 사용한 다른 방법은 위키백과로 작은 n-그램 언어 모델을 학습시킨 뒤 각 웹 문서의 **퍼플렉서티(perplexity, 제4장)** 를 계산하는 것입니다. 퍼플렉서티가 매우 높다면 그 텍스트가 기준과 매우 다르다는 뜻입니다. 더 최근의 파이프라인에서는 기존 LLM에게 페이지 표본의 교육적 가치를 평가하게 한 다음, 이 평가를 전체 크롤링 결과에 재현하는 저렴한 분류기를 학습시키기도 합니다. 이런 단계들을 통틀어 **품질 필터링(quality filtering)** 이라고 합니다.

또 다른 두 필터는 품질이 아니라 해악을 다룹니다. **유해성(toxicity)** 필터는 혐오 표현 같은 내용을 제거하고, **개인 식별 정보(personally identifiable information, PII)** 필터는 이메일 주소나 전화번호 같은 정보를 찾아 가립니다.

모든 필터에는 대가가 따릅니다. 위키백과로 학습한 분류기는 위키백과처럼 보이는 텍스트를 선호하며, 표준 영어보다 방언, 비격식 문체, 소수 언어를 더 자주 버릴 수 있습니다. 필터링 결정은 모델이 무엇을 알고 누구의 언어를 잘 구사하는지를 결정하므로, 도움이 된다고 그냥 가정하지 말고 그 효과를 측정해야 합니다.

## 중복 제거

웹은 복사본으로 가득합니다. 미러 사이트, 배포된 뉴스, 템플릿, 라이선스 문구, 스팸 농장 등이 있습니다. 이것들을 없애는 **중복 제거(deduplication)** 는 여러 면에서 도움이 된다는 것이 밝혀졌습니다(Lee et al., 2022, "Deduplicating Training Data Makes Language Models Better").

- 같은 텍스트를 여러 번 보는 데 연산이 낭비되지 않습니다.
- 모델이 학습 텍스트를 글자 그대로 **암기(memorization)** 하는 일이 줄어듭니다. 이는 개인정보와 저작권 측면에서 중요합니다.
- 테스트 예제가 학습 세트로 새어 들어가는 일이 줄어듭니다.

**정확한 중복 제거**는 쉽습니다. 각 문서, 또는 각 줄이나 문단의 해시(예: SHA-1)를 계산하고 해시마다 한 부만 남기면 됩니다. 데이터를 한 번 훑고 큰 해시 테이블만 있으면 됩니다.

**유사 중복(near-duplicate)** 은 더 어렵습니다. 날짜, 이름, 주변 메뉴만 다른 두 페이지는 해시가 서로 다릅니다. 이들을 비교하려면 먼저 각 문서를 **싱글(shingle)**, 즉 서로 겹치는 단어 n-그램의 집합으로 바꿉니다. $n = 3$일 때 "the cat sat on the mat"이라는 텍스트는 {"the cat sat", "cat sat on", "sat on the", "on the mat"}이라는 집합이 됩니다. 싱글 집합이 $A$와 $B$인 두 문서의 유사도는 **자카드 유사도(Jaccard similarity)** 입니다.

$$
J(A, B) = \frac{|A \cap B|}{|A \cup B|},
$$

즉 공통 싱글의 수를 두 문서에 있는 서로 다른 싱글의 수로 나눈 값입니다. $J = 1$은 두 집합이 같다는 뜻이고, $J = 0$은 공통점이 전혀 없다는 뜻입니다.

$10^9$개 문서의 모든 쌍에 대해 $J$를 계산하는 것은 불가능합니다. 약 $5 \cdot 10^{17}$쌍이기 때문입니다. 문제의 앞쪽 절반은 **MinHash(민해시)** 가 해결합니다. 무작위 해시 함수 $h$를 하나 잡고, 각 문서의 싱글들에 대한 최소 해시값 $\min_{x \in A} h(x)$를 계산합니다. 간단한 논증으로 다음을 보일 수 있습니다.

$$
P\left[\min_{x \in A} h(x) = \min_{x \in B} h(x)\right] = J(A, B).
$$

왜 그럴까요? $A \cup B$에 속한 모든 싱글을 봅시다. 무작위 해시에서는 이들 각각이 가장 작은 값을 가질 확률이 같습니다. $A$와 $B$의 최솟값은 그 가장 작은 싱글이 $A \cap B$에 있을 때에만 정확히 일치하며, 그 확률은 $|A \cap B| / |A \cup B|$입니다. 독립적인 해시 함수 $k$개를 사용하면 문서마다 $k$개의 숫자로 된 **시그니처**를 얻고, 두 시그니처에서 같은 위치의 비율이 $J$의 추정값이 됩니다.

문제의 나머지 절반, 즉 모든 쌍을 비교하지 않는 일은 **지역 민감 해싱(locality-sensitive hashing, LSH)** 이 해결합니다. 길이 $k = b \cdot r$인 시그니처를 $r$개 숫자로 된 $b$개의 밴드로 나눕니다. 두 문서가 적어도 하나의 밴드에서 완전히 일치하면 *후보 쌍*이 됩니다. 두 문서의 자카드 유사도가 $s$라면 그 확률은 다음과 같습니다.

$$
P(\text{후보}) = 1 - (1 - s^r)^b .
$$

여기서 $s^r$는 밴드 하나 전체가 일치할 확률이고, $(1 - s^r)^b$는 $b$개 밴드 모두에서 일치하지 않을 확률입니다. $b = 20$, $r = 5$(해시 100개)일 때, $s = 0.8$인 쌍은 약 $0.9996$, $s = 0.5$인 쌍은 약 $0.47$, $s = 0.3$인 쌍은 약 $0.05$의 확률로 후보가 됩니다. 곡선은 가파른 "S" 모양입니다. 비슷한 쌍은 거의 항상 발견되고, 비슷하지 않은 쌍은 거의 발견되지 않습니다. 실제로는 각 밴드를 버킷으로 해싱하고, 같은 버킷을 공유하는 문서들만 비교합니다.

## 몇 줄로 보는 MinHash

아래 코드는 세 단어 싱글을 만들고, 정확한 자카드 유사도와 MinHash 추정값을 계산합니다. 단순하게 하기 위해 $k$개의 "해시 함수"는 싱글에 서로 다른 접두사를 붙여 CRC32를 적용한 것으로 대신합니다. 실제 시스템은 더 빠르고 더 잘 섞이는 해시 함수 계열을 사용합니다.

```python
import zlib

def shingles(text, n=3):
    """문서의 단어 n-그램(싱글) 집합."""
    words = text.lower().split()
    return {" ".join(words[i:i + n]) for i in range(len(words) - n + 1)}

def jaccard(a, b):
    return len(a & b) / len(a | b)

def minhash(s, num_hashes=128):
    """MinHash 시그니처: num_hashes개 해시 함수 각각의 최솟값."""
    return [min(zlib.crc32(f"{i}:{x}".encode()) for x in s)
            for i in range(num_hashes)]

def estimate(sig_a, sig_b):
    # 일치하는 위치의 비율 ≈ 자카드 유사도
    return sum(x == y for x, y in zip(sig_a, sig_b)) / len(sig_a)

doc1 = "the cat sat on the mat and looked out of the window at the rain"
doc2 = "the cat sat on the mat and looked out of the window at the snow"
doc3 = "gradient descent moves the weights against the gradient of the loss"

s1, s2, s3 = shingles(doc1), shingles(doc2), shingles(doc3)
m1, m2, m3 = minhash(s1), minhash(s2), minhash(s3)
print(f"doc1~doc2: exact {jaccard(s1, s2):.2f}, minhash {estimate(m1, m2):.2f}")
print(f"doc1~doc3: exact {jaccard(s1, s3):.2f}, minhash {estimate(m1, m3):.2f}")
```

이 코드는 첫 번째 쌍에 대해 `exact 0.86, minhash 0.82`를, 두 번째 쌍에 대해 `0.00, 0.00`을 출력합니다. 앞의 두 문서에는 서로 다른 싱글이 모두 14개 있고 그중 12개가 공통이므로 $J = 12/14 \approx 0.86$이며, 해시 128개로 얻은 추정값도 이에 가깝습니다. 전형적인 파이프라인은 추정된 $J$가 0.8 같은 임곗값보다 큰 쌍을 중복으로 보고, 각 그룹에서 문서 하나만 남깁니다.

## 오염과 문서화

연구를 위해서는 한 가지 확인이 더 필요합니다. 바로 **벤치마크 오염(benchmark contamination)** 입니다. 테스트 세트(제39장)의 문제가 학습 데이터에 들어 있다면, 높은 점수는 단지 암기를 보여 줄 뿐일 수 있습니다. 흔한 대응책은 테스트 세트에도 나오는 긴 n-그램(예: 13-그램)을 말뭉치에서 찾아 해당 문서를 제거하고, 어떤 벤치마크에 대해 오염 제거를 했는지 보고하는 것입니다.

마지막으로, 말뭉치는 연구 산출물이므로 문서화해야 합니다. 출처, 라이선스, 필터, 언어별 비율, 알려진 공백 등을 기록합니다. "데이터셋을 위한 데이터시트(datasheets for datasets)" 같은 형식이 이런 정보를 기술합니다. 박사 과정에서 기억해 둘 점은, 재현 가능한 데이터 설명이 모델 설명만큼 중요하다는 것입니다. 아키텍처 효과처럼 보이는 많은 결과가 실제로는 데이터 효과입니다.

## 요약

- 사전 학습 말뭉치는 웹 크롤링 결과, 책, 백과사전, 논문, 코드, 대화의 혼합이며, 혼합 가중치는 조정되는 설계 선택입니다.
- 원시 HTML은 상용구를 제거하면서 텍스트로 변환해야 하고, 각 문서에는 언어 레이블을 붙입니다.
- 휴리스틱 필터(길이, 기호, 반복, 기능어)와 모델 기반 필터(품질 분류기, 퍼플렉서티)는 저품질 텍스트를 제거하지만, 방언과 소수 언어까지 제거할 수 있습니다.
- 정확한 중복은 해시로, 유사 중복은 싱글, 자카드 유사도, MinHash 시그니처, LSH 밴딩으로 제거합니다.
- 중복 제거는 연산을 절약하고 암기를 줄이며 테스트 데이터 유출을 막습니다. 오염 제거와 문서화는 결과를 신뢰할 수 있게 만듭니다.

## 연습 문제

1. 두 MinHash 값이 일치할 확률이 왜 자카드 유사도와 같은지 자신의 말로 설명하십시오.
2. $r = 10$행짜리 밴드 $b = 10$개를 사용할 때, $s = 0.5$와 $s = 0.9$인 쌍이 후보가 될 확률을 계산하십시오. 본문의 $b = 20$, $r = 5$ 값과 비교하십시오. 어느 설정이 더 엄격합니까?
3. 다섯 단어 싱글을 사용하도록 코드를 수정하십시오. `doc1`과 `doc2`의 정확한 유사도와 추정 유사도는 어떻게 바뀌며, 그 이유는 무엇입니까?
4. 영어에는 맞지 않지만 러시아어나 한국어 웹 텍스트에는 의미가 있을 휴리스틱 필터 규칙 세 가지를 만들어 보십시오. 각 규칙에서 무엇이 잘못될 수 있습니까?
