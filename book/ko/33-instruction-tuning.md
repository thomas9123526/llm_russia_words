# 제33장. 지시 튜닝

> **제7부 — 모델의 적응과 정렬** · 수준: 고급
>
> **이 장에서 배울 내용:** 사전 학습된 모델이 지시를 그냥 따르지 않는 이유 · 지시 데이터셋, 채팅 템플릿, 손실 마스킹의 작동 방식 · 지시 데이터에서 가장 중요한 것: 다양성, 품질, 형식

## 대답하는 대신 이어 쓰는 모델

사전 학습만 거친 **기본 모델**(base model, 23장)에게 다음 프롬프트를 준다고 합시다.

> Translate into Russian: "The loss is decreasing."

모델은 다음과 같이 응답할 수도 있습니다.

> Translate into Russian: "The model is overfitting." Translate into Russian: "The learning rate is too high."

이것은 버그가 아닙니다. 모델은 인터넷 문서를 *이어 쓰도록* 학습되었고, 이런 문장은 연습 문제 목록에 자주 등장하며 그 뒤에는 또 다른 연습 문제가 이어집니다. 모델은 번역에 필요한 지식(러시아어를 많이 보았습니다)을 가지고 있지만, 자신이 *대답*해야 한다는 것을 모릅니다. 신중하게 설계한 퓨샷 프롬프트로 대개 대답하게 만들 수는 있지만, 이 방법은 불안정합니다.

**지시 튜닝**(instruction tuning)이 이 문제를 해결합니다. (지시, 원하는 응답) 형태의 많은 예제로 모델을 미세 조정(31장)하여, "지시를 받으면 도움이 되는 응답을 생성한다"는 일반적인 행동을 학습시키는 것입니다. 각 예제에 사람이 작성하거나 승인한 참조 답변이 들어 있기 때문에 지시 튜닝을 **지도 미세 조정**(supervised fine-tuning, SFT)이라고도 부릅니다. 이것은 기본 모델을 어시스턴트로 바꾸는 첫 단계이며, 두 번째 단계인 인간 선호와의 정렬은 34장의 주제입니다.

## 많은 과제에서 제로샷 일반화로

핵심적인 초기 결과는 FLAN(Wei 외, "Finetuned Language Models Are Zero-Shot Learners")에서 나왔습니다. 저자들은 수십 개의 기존 NLP 데이터셋(번역, 감성 분석, 질의응답, 자연어 추론 등)을 가져와 여러 템플릿을 사용해 각각을 자연어 지시 형태로 다시 썼습니다. 예를 들면 다음과 같습니다.

> Is the sentiment of this review positive or negative? Review: "…"

이 과제들로 미세 조정한 뒤, 모델은 지시 튜닝 중에 한 번도 보지 못한 *새로운* 유형의 과제에서 훨씬 좋은 성능을 보였습니다. 이것이 보지 못한 지시에 대한 **제로샷 일반화**(zero-shot generalisation)입니다. T0(Sanh 외)에서도 비슷한 결과가 보고되었습니다. 이 연구 흐름에서 기억할 만한 결론이 두 가지 있습니다.

- **과제의 수와 다양성이 중요합니다.** 과제 군집을 더 추가할수록 보류된 과제에서의 성능이 향상되었습니다.
- **규모가 중요합니다.** 이점은 큰 모델에서 뚜렷하게 나타났고, 아주 작은 모델은 오히려 나빠지기도 했습니다. 아마도 많은 과제를 한꺼번에 학습할 용량이 부족하기 때문일 것입니다.

여기서의 직관은 다중 과제 학습 일반과 같습니다. 모델이 수백 가지의 서로 다른 지시를 보면 각 과제를 단순히 암기할 수 없습니다. 대신 지시를 읽고 그 내용을 수행하는 더 일반적인 기술을 배워야 합니다.

## 지시 데이터는 어디에서 오는가

**지시 데이터셋**(instruction dataset)의 주요 출처는 세 가지입니다.

**1. 변환된 NLP 데이터셋.** FLAN에서처럼 저렴하고 규모가 크지만, 지시는 짧고 정형화된 경우가 많고 답은 레이블 하나나 짧은 구절인 경우가 많습니다. 이것만으로 학습한 모델은 매우 짧게 대답하는 경향이 있습니다.

**2. 사람이 작성한 시범 응답.** InstructGPT(Ouyang 외, 2022)에서는 훈련받은 레이블러들이 프롬프트와 고품질 응답을 작성했습니다. 이렇게 하면 자연스럽고 다양하며 상세한 데이터를 얻지만 비용이 많이 듭니다. 이후의 중요한 결과는 LIMA(Zhou 외, 2023)에서 나왔습니다. 강력한 기본 모델을 신중하게 선별한 약 1,000개의 고품질 예제만으로 미세 조정했는데도 놀라울 만큼 좋은 어시스턴트가 만들어졌습니다. 저자들은 **피상적 정렬 가설**(superficial alignment hypothesis)을 제안했습니다. 거의 모든 지식은 사전 학습에서 습득되며, 지시 튜닝은 주로 상호작용의 형식과 문체를 가르친다는 것입니다.

**3. 모델이 생성한 합성 데이터.** Self-Instruct(Wang 외)에서는 모델에 작은 초기 과제 집합을 주고 새로운 지시, 입력, 출력을 생성하게 한 뒤, 품질이 낮거나 중복된 예제를 걸러 냅니다. Stanford Alpaca는 더 강력한 모델과 함께 이 방식을 사용해 약 52,000개의 예제를 만들었습니다. 오늘날에는 기존 LLM으로 지시 데이터를 생성하고 필터링하는 것이 매우 흔합니다. 저렴하고 확장성이 좋지만, 교사 모델의 오류, 편향, 문체를 그대로 옮겨 올 수 있으며, 교사 모델의 라이선스 조건이 이런 사용을 제한할 수도 있습니다.

여러 언어를 다루는 연구자에게는 추가 질문이 있습니다. 데이터는 어떤 언어로 되어 있습니까? 주로 영어 지시로 튜닝한 모델도 러시아어나 한국어 지시에 대답하는 경우가 많지만(언어 간 전이, 30장), 기계 번역만이 아니라 목표 언어의 원어민 예제가 데이터에 포함될 때 품질, 유창성, 문화적 적합성이 향상됩니다.

## 채팅 템플릿과 손실 마스킹

현대의 어시스턴트는 단일 지시가 아니라 대화로 학습합니다. 대화는 역할이 있는 **턴**(turn)의 연속입니다. 선택적인 **시스템 프롬프트**(system prompt, 어시스턴트를 위한 일반 규칙)가 있고, 그다음에 *사용자*와 *어시스턴트*의 메시지가 번갈아 나옵니다. 하나의 긴 토큰 시퀀스만 보는 디코더 모델에 이를 입력하기 위해, 우리는 **채팅 템플릿**(chat template)으로 대화를 직렬화합니다. 채팅 템플릿은 각 메시지의 시작과 끝을 표시하는 특수 토큰을 가진 고정된 형식입니다. 단순화한 템플릿은 다음과 같을 수 있습니다.

```text
<system>You are a helpful assistant.</system>
<user>Translate into Russian: "The loss is decreasing."</user>
<assistant>«Функция потерь уменьшается».</s>
```

모델 계열마다 고유한 템플릿이 있으며, 모델이 학습할 때 사용한 템플릿을 정확히 사용하는 것이 중요합니다. 추론 시 잘못된 템플릿을 쓰면 품질이 눈에 띄게 떨어질 수 있습니다.

학습 목표는 사전 학습(21장)과 같은 다음 토큰 교차 엔트로피이지만, 중요한 차이가 하나 있습니다. 우리는 모델이 사용자의 말을 예측하도록 학습시키고 싶지 않습니다. 모델이 *응답*을 생성하는 법을 배우기를 원합니다. 그래서 손실은 어시스턴트 토큰에 대해서만 계산합니다. 이를 **손실 마스킹**(loss masking)이라고 합니다. 형식적으로, 토큰 시퀀스 $x_1, \dots, x_T$와 응답 토큰에서 1인 마스크 $m_t \in \{0, 1\}$에 대해 다음과 같습니다.

$$\mathcal{L} = -\frac{1}{\sum_t m_t} \sum_{t=1}^{T} m_t \log p_\theta(x_t \mid x_{<t}),$$

여기서 $p_\theta(x_t \mid x_{<t})$는 파라미터가 $\theta$인 모델이 이전의 모든 토큰이 주어졌을 때 실제 토큰 $x_t$에 부여하는 확률입니다. 프롬프트 토큰은 여전히 입력에 있으므로 모델은 이들에 어텐션을 주지만, 손실에는 아무것도 기여하지 않습니다. 예를 들어 응답이 손실 $0.5$, $1.0$, $0.3$인 세 개의 토큰으로 되어 있다면, 프롬프트의 길이와 관계없이 이 예제의 손실은 $(0.5 + 1.0 + 0.3)/3 = 0.6$입니다. 여러 턴의 대화에서는 보통 모든 어시스턴트 턴에 대해 손실을 계산합니다.

PyTorch에서는 마스킹할 위치의 레이블을 `cross_entropy`의 기본 `ignore_index`인 $-100$으로 설정하여 이를 구현합니다.

```python
import torch
import torch.nn.functional as F

def chat_template(instruction, response):
    prompt = f"<user>{instruction}</user><assistant>"
    return prompt, response + "</s>"

prompt, answer = chat_template("2+2?", "4")
vocab = {ch: i for i, ch in enumerate(sorted(set(prompt + answer)))}
encode = lambda s: [vocab[ch] for ch in s]      # 장난감 문자 단위 토크나이저

p_ids, a_ids = encode(prompt), encode(answer)
input_ids = torch.tensor(p_ids + a_ids)
labels = torch.tensor([-100] * len(p_ids) + a_ids)  # -100 = 손실에서 무시됨
print(len(input_ids), (labels != -100).sum().item())  # 33 5

# 어떤 모델의 로짓: 위치마다 어휘 점수 한 행
torch.manual_seed(0)
logits = torch.randn(len(input_ids), len(vocab))
# 시프트: 위치 t가 토큰 t+1을 예측 (21장)
loss = F.cross_entropy(logits[:-1], labels[1:], ignore_index=-100)
print(f"loss over response tokens only: {loss:.3f}")
```

33개의 문자 토큰 중 답 `4</s>`의 5개 토큰만 학습에 쓰입니다. **시퀀스 종료 토큰**(end-of-sequence token) `</s>`가 응답의 일부라는 점에 주의하십시오. 모델은 *언제 멈출지*를 배워야 합니다. 그렇지 않으면 답을 마친 뒤에도 계속 생성할 것입니다.

## 지시 튜닝을 잘 되게 하는 것

많은 프로젝트의 경험에서 몇 가지 실용적인 교훈을 얻을 수 있습니다.

- **양보다 질이 중요합니다.** 깨끗하고 정확하며 잘 쓰인 수천 개의 예제가 잡음 섞인 수십만 개의 예제보다 나은 경우가 많습니다. 데이터의 틀린 답은 모델에게 자신 있게 틀리는 법을 가르칩니다.
- **다양성이 중요합니다.** 다양한 과제 유형(설명, 코딩, 수학, 바꿔 쓰기, 분류, 대화), 길이, 난이도를 포함하고, 지시를 여러 가지 방식으로 표현하십시오.
- **중복과 오염을 제거하십시오.** 26장에서처럼 거의 중복된 예제를 제거하고, 평가 벤치마크와 겹치는 예제도 제거하십시오. 그렇지 않으면 모델을 과대평가하게 됩니다(39장).
- **지시 튜닝은 지식이 아니라 행동을 가르칩니다.** 피상적 정렬 가설에 따르면, 기본 모델이 어떤 것을 모른다면 SFT가 그것을 확실하게 추가해 주지 않으며, 모델이 정당화할 수 없는 답으로 학습시키면 오히려 환각을 부추길 수도 있습니다.
- **SFT에는 한계가 있습니다.** 모델은 시범 응답을 모방할 수 있을 뿐, 그럴듯한 두 답 중 사람들이 어느 쪽을 선호하는지는 배우지 못합니다. 또한 *하지 말아야 할* 행동의 시범을 작성하기는 어렵습니다. 그래서 SFT 다음에는 보통 선호 기반 정렬(34장)이 이어집니다.

앞 장들의 모든 미세 조정 방법이 여기에도 적용됩니다. 지시 튜닝은 전체 미세 조정으로도, LoRA/QLoRA(32장)로도 할 수 있으며, 파국적 망각(31장)의 위험은 여전히 남아 있습니다.

## 요약

- 기본 모델은 텍스트를 이어 쓰며, 지시 튜닝(지도 미세 조정)은 모델이 지시에 응답하도록 가르칩니다.
- 지시로 표현된 많은 다양한 과제로 학습하면 새로운 지시에 대한 제로샷 일반화가 생기며, 특히 큰 모델에서 그렇습니다.
- 지시 데이터는 변환된 NLP 데이터셋, 사람이 작성한 시범 응답, 모델이 생성한 합성 데이터에서 오며, 크기보다 품질과 다양성이 더 중요합니다.
- 대화는 특수 토큰으로 된 채팅 템플릿으로 직렬화되며, 손실은 시퀀스 종료 토큰을 포함한 어시스턴트 토큰에 대해서만 계산됩니다(손실 마스킹).
- SFT는 주로 형식과 행동을 가르치며, 선호는 다음 단계인 정렬에서 학습됩니다.

## 연습 문제

1. 기본 모델이 지시에 또 다른 지시로 대답할 수 있는 이유를 자신의 말로 설명하십시오.
2. 손실에서 프롬프트 토큰을 마스킹하는 이유를 설명하십시오. 사용자 메시지로도 학습시킨다면 어떤 일이 생길 수 있습니까?
3. 배치에 예제가 두 개 있습니다. 첫 번째 예제의 응답 토큰 손실은 $0.2, 0.4$이고, 두 번째는 $1.0, 0.6, 0.8, 0.6$입니다. (a) 배치의 모든 응답 토큰을 함께 평균하는 경우와 (b) 각 예제를 먼저 평균한 뒤 두 평균을 다시 평균하는 경우의 손실을 계산하십시오.
4. `chat_template`이 `(user, assistant)` 턴의 리스트를 받아 모든 사용자 턴을 마스킹하도록 코드를 확장하십시오. 마스킹되지 않은 토큰의 수가 모든 어시스턴트 응답의 총 길이와 같은지 확인하십시오.
