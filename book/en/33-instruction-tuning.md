> **Part 7 — Adapting and Aligning Models** · Level: Advanced

## A model that continues instead of answering

Give a base pre-trained model (Chapter 23) the prompt

> Translate into Russian: "The loss is decreasing."

and it may well reply with something like

> Translate into Russian: "The model is overfitting." Translate into Russian: "The learning rate is too high."

This is not a bug. The model was trained to *continue* documents from the internet, and a line like this often appears in a list of exercises, where it is followed by more exercises. The model has the knowledge needed to translate (it has seen a lot of Russian), but it does not know that it is expected to *answer*. With a carefully designed few-shot prompt we can usually make it answer, but this is fragile.

**Instruction tuning** fixes this. We fine-tune the model (Chapter 31) on a large set of examples of the form (instruction, desired response), so that it learns the general behaviour "when given an instruction, produce a helpful response". Instruction tuning is also called **supervised fine-tuning** (SFT), because each example contains a reference answer written or approved by people. It is the first step that turns a base model into an assistant; the second step, alignment with human preferences, is the subject of Chapter 34.

## From many tasks to zero-shot generalisation

The key early result came from FLAN (Wei et al., "Finetuned Language Models Are Zero-Shot Learners"). The authors took dozens of existing NLP datasets (translation, sentiment, question answering, natural language inference and so on) and rewrote each one as natural-language instructions using several templates, for example:

> Is the sentiment of this review positive or negative? Review: "…"

After fine-tuning on these tasks, the model performed much better on *new* task types that it had never seen during instruction tuning. This is **zero-shot generalisation** to unseen instructions. Similar results were reported for T0 (Sanh et al.). Two findings from this line of work are worth remembering:

- **The number and diversity of tasks matter.** Performance on held-out tasks improved as more task clusters were added.
- **Scale matters.** The benefit appeared clearly for large models; very small models could even get worse, probably because they lack the capacity to learn many tasks at once.

The intuition is the same as for multi-task learning in general: if the model sees hundreds of different instructions, it cannot simply memorise each task. It must learn the more general skill of reading an instruction and doing what it says.

## Where instruction data comes from

There are three main sources of instruction data.

**1. Converted NLP datasets**, as in FLAN. They are cheap and large, but the instructions are often short and templated, and the answers are often a single label or a short phrase. A model trained only on them tends to give very short answers.

**2. Human-written demonstrations.** In InstructGPT (Ouyang et al., 2022), trained annotators wrote prompts and high-quality responses. This produces natural, varied, detailed data, but it is expensive. An important later result came from LIMA (Zhou et al., 2023): fine-tuning a strong base model on only about 1,000 carefully selected, high-quality examples produced a surprisingly good assistant. The authors proposed the **superficial alignment hypothesis**: almost all knowledge is learned in pre-training, and instruction tuning mainly teaches the format and style of interaction.

**3. Synthetic data generated by models.** In Self-Instruct (Wang et al.), a model is given a small seed set of tasks and asked to generate new instructions, inputs and outputs; low-quality and duplicate examples are then filtered out. Stanford Alpaca used this approach with a stronger model to create about 52,000 examples. Today, generating and filtering instruction data with existing LLMs is very common. It is cheap and scalable, but it can copy the errors, biases and style of the teacher model, and the licence terms of the teacher model may restrict this use.

For a multilingual researcher, there is an extra question: in which languages is the data? A model tuned mostly on English instructions often still answers Russian or Korean instructions (cross-lingual transfer, Chapter 30), but quality, fluency and cultural fit improve when the data includes native examples in the target language, not only machine translations.

## Chat templates and loss masking

Modern assistants are trained on conversations, not single instructions. A conversation is a sequence of **turns** with roles: an optional **system prompt** (general rules for the assistant), then alternating *user* and *assistant* messages. To feed it to a decoder model, which only sees one long token sequence, we serialise the conversation with a **chat template**: a fixed format with special tokens that mark where each message starts and ends. A simplified template might look like this:

```text
<system>You are a helpful assistant.</system>
<user>Translate into Russian: "The loss is decreasing."</user>
<assistant>«Функция потерь уменьшается».</s>
```

Each model family has its own template, and it is important to use exactly the template the model was trained with; a wrong template at inference time can noticeably reduce quality.

The training objective is the same next-token cross-entropy as in pre-training (Chapter 21), with one important change. We do not want to train the model to predict the user's words; we want it to learn to produce the *responses*. So we compute the loss only on the assistant tokens. This is called **loss masking**. Formally, for a sequence of tokens $x_1, \dots, x_T$ and a mask $m_t \in \{0, 1\}$ that is 1 for response tokens,

$$\mathcal{L} = -\frac{1}{\sum_t m_t} \sum_{t=1}^{T} m_t \log p_\theta(x_t \mid x_{<t}),$$

where $p_\theta(x_t \mid x_{<t})$ is the probability the model with parameters $\theta$ assigns to the true token $x_t$ given all previous tokens. The prompt tokens are still in the input, so the model attends to them, but they contribute nothing to the loss. For example, if a response has three tokens with losses $0.5$, $1.0$ and $0.3$, the loss of this example is $(0.5 + 1.0 + 0.3)/3 = 0.6$, no matter how long the prompt is. In multi-turn conversations, the loss is usually computed on all assistant turns.

In PyTorch this is done by setting the labels of masked positions to $-100$, the default `ignore_index` of `cross_entropy`:

```python
import torch
import torch.nn.functional as F

def chat_template(instruction, response):
    prompt = f"<user>{instruction}</user><assistant>"
    return prompt, response + "</s>"

prompt, answer = chat_template("2+2?", "4")
vocab = {ch: i for i, ch in enumerate(sorted(set(prompt + answer)))}
encode = lambda s: [vocab[ch] for ch in s]      # toy character-level tokenizer

p_ids, a_ids = encode(prompt), encode(answer)
input_ids = torch.tensor(p_ids + a_ids)
labels = torch.tensor([-100] * len(p_ids) + a_ids)  # -100 = ignored by the loss
print(len(input_ids), (labels != -100).sum().item())  # 33 5

# Logits from some model: one row of vocabulary scores per position
torch.manual_seed(0)
logits = torch.randn(len(input_ids), len(vocab))
# Shift: position t predicts token t+1 (Chapter 21)
loss = F.cross_entropy(logits[:-1], labels[1:], ignore_index=-100)
print(f"loss over response tokens only: {loss:.3f}")
```

Of the 33 character tokens, only the 5 tokens of the answer `4</s>` are trained on. Note that the end-of-sequence token `</s>` is part of the response: the model must learn *when to stop*, otherwise it will keep generating after its answer.

## What makes instruction tuning work well

Experience from many projects gives a few practical lessons.

- **Quality beats quantity.** A few thousand clean, correct, well-written examples are often better than hundreds of thousands of noisy ones. Wrong answers in the data teach the model to be confidently wrong.
- **Diversity matters.** Cover many task types (explanation, coding, mathematics, rewriting, classification, dialogue), lengths, and difficulty levels, and phrase instructions in many different ways.
- **Deduplicate and decontaminate.** As in Chapter 26, remove near-duplicates, and remove examples that overlap with evaluation benchmarks, otherwise you will overestimate your model (Chapter 39).
- **Instruction tuning teaches behaviour, not knowledge.** In line with the superficial alignment hypothesis, if the base model does not know something, SFT will not reliably add it, and training on answers the model cannot justify may even encourage hallucination.
- **SFT has limits.** The model can only imitate the demonstrations; it does not learn which of two plausible answers people prefer, and it is hard to write demonstrations of how *not* to behave. This is why SFT is usually followed by preference-based alignment (Chapter 34).

All the fine-tuning methods from earlier chapters apply here: instruction tuning can be done with full fine-tuning or with LoRA/QLoRA (Chapter 32), and the risk of catastrophic forgetting (Chapter 31) remains.

## Summary

- A base model continues text; instruction tuning (supervised fine-tuning) teaches it to respond to instructions.
- Training on many diverse tasks phrased as instructions gives zero-shot generalisation to new instructions, especially for large models.
- Instruction data comes from converted NLP datasets, human demonstrations, and synthetic data generated by models; quality and diversity matter more than size.
- Conversations are serialised with a chat template of special tokens; the loss is computed only on assistant tokens (loss masking), including the end-of-sequence token.
- SFT mainly teaches format and behaviour; preferences are learned in the next stage, alignment.
