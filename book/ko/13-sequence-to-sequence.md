## 한 시퀀스에서 다른 시퀀스로

"I love you"를 러시아어 «Я тебя люблю»나 한국어 "사랑해"로 번역하는 신경망을 어떻게 만들 수 있을까요? 영어 문장은 세 단어, 러시아어도 세 단어, 한국어는 한 단어입니다. 어순도 다릅니다. 제11장의 언어 모델은 입력 토큰마다 출력을 하나씩 내므로, 입력과 출력이 위치별로 정렬되어 있습니다. 번역은 그렇지 않습니다. 출력에는 자기만의 길이와 자기만의 순서가 있습니다.

많은 문제가 이런 형태를 띱니다. 요약은 긴 문서를 짧은 텍스트로 바꿉니다. 질의응답은 질문을 답으로 바꿉니다. 음성 인식은 오디오 프레임의 시퀀스를 문자의 시퀀스로 바꿉니다. "27 November 2026"이라고 쓴 날짜를 "2026-11-27"로 바꾸는 것조차 한 시퀀스에서 다른 시퀀스로의 변환입니다. 이런 과제를 위한 모델을 **시퀀스-투-시퀀스**(sequence-to-sequence, seq2seq) 모델이라고 부릅니다.

2014년 Sutskever, Vinyals, Le가, 그리고 이와 나란히 Cho와 동료들이 제안한 해결책은 단순하고 우아합니다. 순환 신경망 두 개를 사용하는 것입니다.

1. **인코더**(encoder)는 입력 문장 전체를 읽고 이를 하나의 벡터, 즉 **문맥 벡터**(context vector) $c$로 압축합니다.
2. **디코더**(decoder)는 이 벡터에서 출발하여 출력 문장을 한 번에 토큰 하나씩 생성합니다. $c$에 "조건화된" 언어 모델과 같습니다.

이것이 **인코더–디코더 구조**(encoder–decoder architecture)입니다. 이 책에서 가장 중요한 아이디어 중 하나입니다. 원래의 트랜스포머(제19장)와 T5 같은 모델은 RNN을 어텐션으로 바꾸었지만, 인코더와 디코더로 나누는 이 구분은 그대로 유지합니다.

## 인코더와 디코더

원문 문장을 $x_1, \dots, x_S$, 목표 문장을 $y_1, \dots, y_T$라고 합시다. $S$와 $T$는 다를 수 있다는 점에 유의하십시오.

인코더는 RNN입니다(실제로는 보통 제12장의 LSTM이나 GRU). 원문 토큰을 하나씩 읽습니다.

$$h_s = \operatorname{RNN}_{enc}(x_s, h_{s-1}), \quad s = 1, \dots, S$$

마지막 은닉 상태가 문맥 벡터가 됩니다: $c = h_S$. 인코더가 제 역할을 했다면 $c$에는 번역에 필요한 모든 것이 들어 있습니다.

디코더는 자기만의 가중치를 가진 또 하나의 RNN입니다. 초기 상태는 문맥 벡터, 즉 $s_0 = c$입니다. 매 단계 이전 출력 토큰을 받아 상태를 갱신합니다.

$$s_t = \operatorname{RNN}_{dec}(y_{t-1}, s_{t-1})$$

$$P(y_t \mid y_{<t}, x) = \operatorname{softmax}(W_{out}\, s_t + b_{out})$$

여기서 $y_{<t}$는 "위치 $t$ 이전의 모든 목표 토큰"을 뜻하고, $W_{out}$은 디코더 상태를 어휘의 단어마다 하나의 점수(로짓)로 바꿉니다. 어떤 변형에서는 $c$를 처음에만이 아니라 매 단계 디코더에 입력하기도 합니다.

이것이 작동하려면 두 가지 세부 사항이 필요합니다. 첫째, 디코더는 아직 아무 단어도 만들지 않은 1단계에서도 무언가를 읽어야 합니다. 그래서 $y_0$로 `<bos>`("시퀀스 시작") 같은 **특수 토큰**(special token)을 사용합니다. 둘째, 디코더는 출력이 언제 끝났는지 결정할 수 있어야 합니다. 학습할 때 모든 목표 문장 끝에 **시퀀스 종료 토큰**(end-of-sequence token) `<eos>`를 붙이고, 생성할 때는 디코더가 이 토큰을 내놓는 즉시 멈춥니다.

종합하면 디코더는 확률의 연쇄 법칙(제6장)으로 출력 문장 전체의 확률을 정의합니다.

$$P(y_1, \dots, y_T \mid x) = \prod_{t=1}^{T} P(y_t \mid y_{<t}, x)$$

이는 일반적인 언어 모델(제1장)과 같은 분해인데, 다만 모든 인수가 원문 문장 $x$에도 의존합니다. 따라서 seq2seq 모델은 **조건부 언어 모델**(conditional language model)입니다.

다음은 무작위(학습되지 않은) 가중치를 가진 NumPy 장난감 인코더–디코더입니다. 작동하는 번역기가 아니라 데이터의 흐름을 보여 줍니다.

```python
import numpy as np

rng = np.random.default_rng(0)
V, d = 6, 8                       # 어휘 크기, 은닉 크기
BOS, EOS = 0, 1                   # 특수 토큰: 시퀀스 시작 / 끝
E = rng.normal(0, 0.5, (V, d))    # 임베딩 테이블 (제5장)
W_enc, U_enc = rng.normal(0, 0.5, (d, d)), rng.normal(0, 0.5, (d, d))
W_dec, U_dec = rng.normal(0, 0.5, (d, d)), rng.normal(0, 0.5, (d, d))
W_out = rng.normal(0, 0.5, (V, d))   # 은닉 상태 -> 어휘에 대한 로짓

def encode(src):
    h = np.zeros(d)
    for tok in src:                    # 원문 문장 전체를 읽는다
        h = np.tanh(W_enc @ E[tok] + U_enc @ h)
    return h                           # 문맥 벡터 c = 마지막 은닉 상태

def greedy_decode(c, max_len=10):
    s, tok, out = c, BOS, []           # 디코더는 c와 <bos>에서 시작
    for _ in range(max_len):
        s = np.tanh(W_dec @ E[tok] + U_dec @ s)
        tok = int(np.argmax(W_out @ s))   # 가장 확률이 높은 토큰 선택
        if tok == EOS:
            break
        out.append(tok)                # 자신의 예측을 다시 입력으로
    return out

c = encode([2, 3, 4, 5])
print("context vector:", np.round(c, 2))
print("generated ids:", greedy_decode(c))
```

가중치가 무작위이므로 출력에는 의미가 없고, 이번 실행에서 디코더는 끝내 `<eos>`를 내놓지 않습니다. `max_len` 때문에 멈출 뿐입니다. 모든 생성 반복문에는 길이 제한이 필요하다는 유용한 교훈입니다.

## 교사 강요로 학습하기

학습할 때는 번역된 텍스트의 **병렬 말뭉치**(parallel corpus) 등에서 얻은 문장 쌍(원문, 목표)이 있습니다. 손실은 매 단계 정답 목표 토큰의 교차 엔트로피(제8장)를 문장 전체에 대해 합한 것입니다.

$$\mathcal{L} = -\sum_{t=1}^{T} \log P(y_t \mid y_{<t}, x)$$

기울기는 디코더에서 $c$를 거쳐 인코더로 거슬러 흐르므로, 두 네트워크가 종단 간(end-to-end)으로 함께 학습됩니다.

중요한 질문이 있습니다. 학습 중 단계 $t$에서 디코더는 무엇을 입력으로 받아야 할까요? 자신의 이전 예측일까요, 아니면 올바른 이전 단어일까요? 학습 초기에는 모델의 예측이 대부분 틀립니다. 이를 다시 입력하면 실수 하나가 디코더를 이상한 상태로 몰아가고, 이후 모든 단계가 쓰레기로부터 배우게 됩니다. 그래서 모델이 무엇을 예측했든 학습 데이터의 **올바른** 이전 토큰 $y_{t-1}$을 입력합니다. 이를 **교사 강요**(teacher forcing)라고 합니다. 선생님이 다음 질문마다 학생에게 정답을 먼저 알려 주는 셈입니다. 교사 강요는 학습을 안정적이고 빠르게 만들며, 디코더의 모든 단계를 알려진 입력으로 계산할 수 있게 해 줍니다.

교사 강요에는 대가가 있습니다. 생성할 때는 선생님이 없습니다. 코드의 반복문처럼 디코더는 자기 예측을 입력으로 써야 합니다. 따라서 모델은 학습 중 한 번도 보지 못한 상황, 즉 자기 실수 이후의 상황에서 평가됩니다. 이 불일치를 **노출 편향**(exposure bias)이라고 합니다. 여러 해결책이 있지만(예를 들어 학습 중에 가끔 모델 자신의 예측을 입력하는 scheduled sampling), 교사 강요는 seq2seq 모델과 이후 장의 대규모 언어 모델 모두를 학습시키는 표준 방법으로 남아 있습니다.

## 출력 생성: 탐욕적 디코딩과 빔 서치

생성할 때 우리는 가장 확률이 높은 출력 문장을 원합니다.

$$\hat{y} = \arg\max_{y} P(y \mid x)$$

가능한 모든 문장을 시도하는 것은 불가능합니다. 어휘가 $V$개 단어이면 길이 $T$인 문장이 $V^T$개 있습니다. 가장 단순한 근사는 **탐욕적 디코딩**(greedy decoding)입니다. 위 코드의 `np.argmax`처럼 매 단계 가장 확률이 높은 토큰 하나를 고릅니다. 빠르지만, 지금 가장 좋아 보이는 선택이 나중에 나쁜 문장으로 이어질 수 있습니다.

**빔 서치**(beam search)는 더 많은 선택지를 열어 둡니다. 부분 문장 하나 대신 가장 좋은 $k$개(이를 "빔"이라 하며, $k$는 보통 4에서 10 사이)를 유지합니다. 매 단계 각각을 가능한 모든 다음 토큰으로 확장하고, 모든 후보를 전체 로그 확률 $\sum_t \log P(y_t \mid y_{<t}, x)$로 평가한 뒤, 가장 좋은 $k$개를 남깁니다. $k = 2$인 작은 예를 들어 봅시다. 1단계 후 빔이 {"Я"(로그 확률 $-0.4$), "Мне"($-1.2$)}이면, 2단계에서 둘 다 확장하여 {"Я тебя"($-0.9$), "Я люблю"($-1.5$)}를 남길 수 있습니다. 1단계의 두 번째 가설은 버려졌습니다. 긴 문장일수록 음수 항이 더 많이 쌓이므로, 빔 서치는 매우 짧은 출력을 선호하지 않도록 보통 점수를 길이로 나눕니다. 샘플링을 포함한 디코딩 전략은 제24장에서 다시 다룹니다.

Sutskever 등은 흥미로운 요령도 발견했습니다. 원문 문장을 **역순으로** 인코더에 넣으면 번역 품질이 좋아졌습니다. 순서를 뒤집으면 원문의 첫 단어들이 시간상으로 번역문의 첫 단어들 가까이에 오게 되어, 초기 의존성이 짧아지고 배우기 쉬워집니다. 이 요령은 다음에 다룰 진짜 문제를 암시합니다.

## 병목 문제

인코더는 원문 문장 전체를, 그것이 5단어이든 50단어이든, 고정 크기의 벡터 $c$ 하나로 압축해야 합니다. 짧은 문장에서는 잘 작동하지만 긴 문장에서는 그렇지 않습니다. Cho 등(2014)은 이런 모델의 번역 품질이 원문 문장이 길어질수록 급격히 떨어진다는 것을 관찰했습니다.

이유는 쉽게 이해할 수 있습니다. 예컨대 숫자 1,000개짜리 벡터가 문단 전체의 의미, 어순, 이름, 문법적 세부 사항을 담아야 하고, 그것도 디코더가 매 단계 사용할 수 있는 형태로 담아야 합니다. 한편 디코더는 순간마다 다른 정보가 필요합니다. 동사를 만들 때는 원문의 동사가, 이름을 만들 때는 그 이름이 필요합니다. 그런데 디코더는 늘 똑같은 압축 요약만 봅니다. 이것이 기본 인코더–디코더의 **정보 병목**(information bottleneck)입니다.

인간 번역가를 생각해 보십시오. 번역가는 문단 전체를 읽고 책을 덮은 다음 기억에 의존해 번역문을 쓰지 않습니다. 원문을 몇 번이고 다시 보면서, 매번 지금 번역하는 부분에 집중합니다. 제14장은 신경망에 바로 이 능력을 주는 방법을 보여 줍니다. 그 메커니즘을 **어텐션**(attention)이라고 하며, 이것이 이 분야를 바꾸어 놓았습니다.

## 요약

- 시퀀스-투-시퀀스 모델은 번역이나 요약처럼 입력 시퀀스를 길이가 다른 출력 시퀀스로 바꿉니다.
- 인코더 RNN은 원문을 읽어 문맥 벡터 $c$를 만들고, 디코더 RNN은 $c$로부터 목표 문장을 한 번에 토큰 하나씩 생성합니다.
- 특수 토큰 `<bos>`와 `<eos>`는 디코더를 시작시키고 출력의 끝을 표시합니다. 이 모델은 조건부 언어 모델 $P(y \mid x) = \prod_t P(y_t \mid y_{<t}, x)$입니다.
- 교사 강요는 학습 중에 올바른 이전 토큰을 입력합니다. 생성 때와의 불일치를 노출 편향이라고 합니다.
- 탐욕적 디코딩은 매 단계 최선의 토큰을 고르고, 빔 서치는 가장 좋은 부분 출력 $k$개를 유지합니다.
- 고정 크기의 문맥 벡터 하나는 병목이며, 긴 문장에서 번역 품질이 떨어집니다. 이것이 어텐션의 동기입니다.

## 연습 문제

1. 교사 강요가 무엇인지, 왜 학습을 쉽게 만드는지, 생성할 때 어떤 문제를 일으키는지 자신의 말로 설명하십시오.
2. 어휘가 10,000개 단어일 때 길이 5인 출력 문장은 몇 개 존재합니까? $k = 4$인 빔 서치는 매 단계(가장 좋은 4개를 남기기 전에) 몇 개의 후보를 평가합니까?
3. 디코더가 3토큰 출력에서 선택된 토큰들에 확률 $0.5$, $0.4$, $0.9$를 주었습니다. 문장의 로그 확률(자연로그)과 길이로 정규화한 점수(3으로 나눈 값)를 계산하십시오.
4. 위 코드의 `greedy_decode`를 고쳐, 선택된 토큰들의 로그 확률 합도 함께 돌려주게 하십시오. (힌트: `W_out @ s`에 소프트맥스를 적용하고 선택된 원소의 로그를 취하십시오.)
